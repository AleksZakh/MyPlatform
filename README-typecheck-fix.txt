Space: исправление типов после согласования H3
============================================

Установка
---------
1. Остановите dev-сервер и сохраните резервную копию изменяемых исходников.
2. Распакуйте этот ZIP в корень проекта MyPlatform с заменой файлов.
   В архиве только изменённые файлы. package.json и схема Prisma не заменяются.
3. Выполните:
   npx prisma generate
   npx nuxi prepare
   npx nuxi typecheck 2>&1 | tee typecheck-after-fixes.log
4. Перезапустите сервер разработки. В VS Code: Developer: Reload Window.

Миграции БД для этого исправления НЕ нужны.

Что исправлено
--------------
- Prisma-запросы справочников приведены к реальным полям и связям схемы.
- Производитель берётся из ReceiptMaterial, протокол и поступление связаны
  через SamplingTest. Связи 1:1 проверяются непосредственно, без _count.
- Запрет удаления поступлений и протоколов сохранён.
- Старые имена multipart-полей и структура ответов для справочных форм
  поддерживаются через server/utils/lab-handbook-dto.ts. Это адаптер API,
  а не возвращение старой структуры в БД.
- qualDate в существующей форме подписано «Дата поступления», поэтому
  оно соответствует receiptDate. qualityDocumentDate — отдельная дата,
  её эти старые поля не перезаписывают.
- Проверка существования номера протокола использует findFirst: номер
  не объявлен уникальным в БД. Прежняя проверка дубликатов сохранена;
  ограничение уникальности в БД не добавлялось.
- Исправлены реальные поля в создании/редактировании актов, поступлений,
  протоколов, включая участки, где any скрывал ошибки запросов.
- При создании отдельного акта требуется ID поступления, поскольку эта
  связь обязательна в Prisma. Пустое значение даёт понятную ошибку 400.
- Удалён оставшийся вызов clearLocationSuggestionState после удаления списка мест.
- Компоненты отображения принимают null; исторические протоколы могут не иметь номера/результата.
- Обновление AD-кэша использует listDomainUsers, возвращающий DirectoryUser[].
- Объединены декларации User; учтены поля существующего регистрационного ответа.
- Собственные функции паролей переименованы в hashSpacePassword и
  verifySpacePassword. Алгоритм и формат сохранённых хешей не менялись.

Загрузка файлов
---------------
POST /api/lab/sampling-test/upload теперь использует обычную сессию Space
и requirePermission для lab.sampling-tests / UPDATE. Исключение этого URL
из серверного middleware авторизации удалено. Вход скрипта через
POST /api/auth/login выдаёт необходимую cookie; Kerberos-заголовки и
самостоятельно заданный X-Migration-Key не являются заменой этой сессии.

Принимается PDF (до 50 МиБ). Проверка размера выполняется после разбора
multipart; лимит всего запроса при необходимости задаётся также в nginx.
Принимаются dbRecordId или samplingTestId; если переданы оба, они должны совпасть.
Метаданные каталогов берутся из записи Space по ID:
  объект / место / дата отбора / act_<номер>_<id>_<UUID>.pdf
Поля date/objectName/location из CSV не определяют серверный путь.
Корень: LAB_FILES_ROOT или /var/www/uploads-storage/files по умолчанию.
Процесс Nuxt должен иметь права записи в этот каталог.

В БД сохраняется ОТНОСИТЕЛЬНЫЙ путь без /files/, поскольку текущий
FileViewerModal и существующий загрузчик добавляют /files/ при открытии.
Ответ содержит path (относительный путь) и url (готовый адрес /files/...).
Существующие файлы и ранее записанные пути пакет не переносит и не исправляет.
При загрузке нового документа ссылка на акт обновляется; старый файл
автоматически не удаляется. При конфликте обновления БД новая копия удаляется.
Повторный успешный запрос создаёт новую копию; идемпотентность этим пакетом не добавлялась.

Проверки
--------
- Prisma validate: успешно для схемы из присланного архива.
- Prisma Client 6.19.3 сгенерирован из этой схемы, без подключения к БД.
- Отдельная строгая проверка изменённых лабораторных API, DTO и AD-вызовов:
  без ошибок (TypeScript 5.9.3, локальный тестовый контекст Nuxt).
- Проверено соответствие сериализованных DTO интерфейсам Receipt/Protocol форм.
- Изменённые Vue SFC успешно разобраны и скомпилированы compiler-sfc.
- Тесты загрузчика на подставных ответах: 401/403, ID, отказ HTML,
  отсутствующая запись, запись файла и ссылки, удаление копии при конфликте.
- Проверены DTO для записей с протоколом/без протокола и разные даты
  поступления и документа о качестве.

Полный nuxi typecheck и работа с боевой БД/AD здесь не запускались:
в архиве нет всего проекта и его установленных зависимостей.
После установки пришлите typecheck-after-fixes.log, если ошибки останутся.
