# dis_user_works — результаты и порядок переноса

## Подтверждено по присланным примерам

- 10 строк, 18 столбцов. Все 10 имеют статус completed; это не доказывает заполненность факта.
- dog_works — 2 записи непосредственно по договорам. building содержит пробел, трактуется как отсутствие кода сооружения.
- build_works — 8 записей по сооружениям. building содержит код ИССО, сохраняемый строкой: 11400101, 11501620, 11501613, 11200340.
- work_id соответствует шифрам библиотеки, например 105, 102, 305, 312.
- user_fio — текст имени, не ID аккаунта. При импорте нельзя автоматически связывать неоднозначные инициалы с пользователем.
- В 7 примерах completed соседствует с неполным фактом. Фактические даты и часы нельзя заполнять плановыми.
- History не рассматривается как новая история событий и не переносится.

Новые ID взяты из успешного APPLY-отчёта, а не рассчитаны или угаданы. В обеих старых договорных работах user_work_id пуст. Поэтому совпадение реквизитов и шифра является только кандидатом: запись может отражать старое назначение, другую версию или отдельное выполнение. Автоматического объединения нет.

Для 8 build_works нужно сопоставление с исходной таблицей работ сооружений. Только персональная выборка не позволяет проверить прямые ссылки, повторные задания, различия плана/факта и выбор основного источника.

## Предлагаемая модель без двойного учёта — пока не внедрена

1. Работа договора или работа сооружения — одна основная запись задания, отображаемая в договоре и в персональном списке через связь.
2. Старый ID dis_user_works и исходные поля сохраняются в отдельной таблице происхождения/соответствий. Такая запись сама по себе не добавляет вторую трудоёмкость.
3. Сначала проверяются прямые старые ссылки. Совпадения по договору, коду сооружения, шифру и исполнителю помогают найти кандидатов, но не являются достаточным ключом для объединения.
4. Если у одного задания было несколько исполнителей или несколько выполнений, их нельзя сворачивать в одну запись без уточнения модели. Раздельные персональные трудозатраты вводятся только при подтверждении их смысла, а не суммируются поверх общей трудоёмкости автоматически.
5. Конфликтные значения сохраняются для сверки; уже импортированные 5 821 работа не перезаписываются из персональной таблицы.
6. После согласования соответствий — отдельный PLAN с отчётом, затем атомарный APPLY с аудитом и повторным запуском без дублей.
