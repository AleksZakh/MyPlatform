# УПТС: договоры и библиотека работ — 03.11.2026

Это очередной пробный шаг. Главная единица интерфейса — договор, в рамках которого выполняются земельно-кадастровые работы. Подробный состав карточки договора и правила завершения ещё предстоит согласовать.

## Что изменилось

- На главной — реестр договоров, фильтр договора и показатели связанных задач. Кнопка верхней панели — «+ Договор».
- «Договоры» перенесены к началу навигации; добавлена «Библиотека работ». Прежние проекты доступны через «Проекты Space».
- В библиотеке — список работ и шаблоны, фильтр типа, поиск, архив. Работы и шаблоны можно создавать, редактировать, архивировать и восстанавливать. Шаблон можно копировать и менять порядок его работ.
- Шесть типов: земельный участок, ОКС, ЗОУИТ, ИПЭ, межевые знаки, иное. Миграция однократно добавляет 18 работ и 5 базовых шаблонов. Для «Иного» работы вводятся вручную; при необходимости можно составить собственный шаблон этого типа.
- Повтор «Регистрация права» в исходном перечне земельных работ внесён один раз. «НГС» и «ПП» сохранены без предположений об их расшифровке.
- При создании договора предлагается подходящий действующий шаблон. Его можно заменить или создать договор без начального набора. Для «Иного» — ручной список. Добавление работ к существующему договору выполняется отдельной кнопкой с предварительным просмотром.
- Работы создаются как общие задачи Space с прямой привязкой к договору. Исполнители и сроки изначально не назначены. Изменение/архивирование работы или шаблона не изменяет уже созданные задачи.
- Повторная отправка одного запроса не создаёт второй договор/набор. Новое осознанное применение набора из нового окна добавляет ещё один набор.
- Excel учитывает фильтр договора, содержит тип договора и связь задачи с договором. Остальные листы сохранены.

## Права и хранение

Допуск в УПТС по подразделению, группе и системной административной роли сохраняется. Членство в УПТС само по себе не открывает чужие личные проекты или договоры.

Создание отдельного договора автоматически создаёт рабочую область на существующей модели проекта Space и папку договора. С 05.11.2026 в форме задаётся видимость, по умолчанию — всем сотрудникам управления. Детали и ограничения описаны в [обновлении карточек и видимости](upts-contracts-ui.md). Прежние области, права и пути файлов сохраняются.

Наборы к существующему договору применяет владелец/руководитель его активной рабочей области. Библиотеку просматривают допущенные сотрудники УПТС; изменяют системные администраторы либо сотрудники УПТС с правом UPDATE на существующий ресурс `projects.shared`. Новые права автоматически не выдаются.

## Существующие данные

У старых договоров тип остаётся пустым до явного выбора сотрудником. Задачи автоматически не распределяются между договорами, даже если в области пока один договор. Для ручной привязки откройте задачу и выберите поле «Договор»; доступны договоры той же рабочей области. Сервер отклоняет межпроектные привязки.

При выборе отдельного договора показатели и задачи учитывают только его привязанные задачи. При выборе всех договоров видны также прежние непривязанные задачи; поэтому суммарные показатели всего раздела могут быть больше суммы строк реестра договоров.

Участки/объекты, их готовность, команда и архив пока остаются на уровне рабочей области Space. Отдельное распределение объектов, независимые статусы/архив договоров и расширенная карточка договора не утверждались и здесь не вводятся.

## Журнал событий

Создание/изменение договора, создание задач, создание/изменение/архивирование/восстановление работ и шаблонов, применение наборов и Excel-экспорт записываются в существующий журнал. Копирование шаблона регистрируется как создание нового шаблона. Для изменений библиотеки записываются прежние и новые значения полей; для применения — договор, шаблон, его версия, названия и идентификаторы созданных задач.

Бизнес-изменения новых API и их записи в журнал выполняются в одной транзакции: если запись журнала не удалась, изменение не подтверждается. Повтор запроса без нового изменения не создаёт дубликата события. Технические действия интерфейса (переключение вкладки, поиск, раскрытие формы) не считаются изменениями данных.

## Установка

1. Распакуйте архив в отдельный каталог. Из него выполните проверку, затем применение к исходникам:

```bash
python3 install-update.py ~/Projects/MyPlatform
python3 install-update.py ~/Projects/MyPlatform --apply
```

Установщик сначала проверяет все правки, при конфликте останавливается без записи. При применении создаёт `backup-*`, сохраняет посторонние правки вне изменяемых участков. Git, БД, процессы и зависимости не изменяет.

2. Проверьте `git diff` и текущую ветку `feature/auth-access-refactor`. Закоммитьте, отправьте изменения и получите их в исходниках сервера установленным у вас способом.
3. Требуется новая миграция `20261103160000_upts_contract_works`. Перед обновлением сохраните штатную резервную копию БД. Миграция добавляет поля/таблицы и начальные записи; старые записи и файлы не удаляет. Новых npm-зависимостей нет.
4. Если используется существующий `space-release`, подготовьте релиз обычным способом. Для полученного идентификатора выполните:

```bash
sudo /usr/local/sbin/space-release db-status RELEASE_ID
sudo /usr/local/sbin/space-release migrate RELEASE_ID
sudo /usr/local/sbin/space-release activate RELEASE_ID --db-compatible
```

Замените `RELEASE_ID` фактическим идентификатором, выведенным при подготовке. Не активируйте новый код до успешной миграции. Подготовка релиза уже генерирует Prisma Client. Откат кода не отменяет миграцию и не удаляет созданные договоры.

Для другого процесса развёртывания: в окружении нужной БД выполните `prisma migrate deploy`, сгенерируйте Prisma Client и соберите/перезапустите приложение штатным способом. Не используйте `db push` или `migrate reset` для рабочей БД.

## Проверка после установки

1. Откройте УПТС: центр — реестр договоров, верхняя кнопка — «+ Договор».
2. В библиотеке проверьте 7 земельных работ, 7 работ ОКС, 2 ЗОУИТ, 1 ИПЭ, 1 работу межевых знаков. В разделе шаблонов — базовые наборы этих типов.
3. Создайте пробный договор с земельным шаблоном: должно появиться 7 связанных задач, без назначенных исполнителей и сроков, и папка договора.
4. Для «Иного» введите две строки работ — должны появиться две задачи. Проверьте просмотр по договору, Excel, команду и журнал.
5. Измените копию шаблона: существующие задачи должны сохранить прежние названия/состав.
