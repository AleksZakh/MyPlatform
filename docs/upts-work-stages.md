# УПТС — этапы выполнения работ

Пакет Space-UPTS-work-stages-20261105. База: Space-UPTS-object-general-20261105.

## Форма объекта

Модальное окно создания/редактирования объекта занимает высоту viewport минус 32 px
(по 16 px сверху и снизу). На узком экране — минус 20 px. Высота не зависит от вкладки;
содержимое прокручивается внутри. Это опциональный режим общего Modal, включённый
только в карточке объекта. Остальные модальные окна сохраняют прежнее поведение.

Количество этапов в общих параметрах относится исключительно к работам.
Поле «Этап» в характеристиках относится к строительству дороги и не менялось.
Если количество этапов не заполнено, используется один этап выполнения работ.

В таблице работ есть флажки выделения, название, номер этапа, ответственная роль,
ожидаемый результат; при редактировании также состояние работы. Флажок заголовка
выделяет все строки. Панель «Этап для выбранных» / «Назначить этап» назначает один
номер всем выделенным строкам; флажки не исключают работы из набора.
Для новой работы первоначально выбран этап 1. Можно назначить номер индивидуально.
Каждая работа относится к одному этапу. Копии работы по всем этапам не создаются.

При уменьшении числа этапов назначения не сбрасываются автоматически. Строки вне
нового диапазона помечаются; сохранение требует переназначить эти работы. То же
правило применяется при очистке количества этапов (тогда остаётся этап 1).
Переключение вкладок сохраняет назначения. Работы ручного ввода также поддерживают этапы.
В окне добавления работ в существующий объект назначение доступно для библиотеки,
шаблона и своей работы. Сведения об этапе видны в карточке работы и экспорте Excel.

## Хранение и совместимость

Номер хранится в WorkTask.uptsWorkMeta.stageNumber. Существующие поля снимка библиотеки
сохраняются. У старых работ без stageNumber подразумевается этап 1; миграция не нужна.
Шаблоны библиотеки не меняются: номера этапов относятся к конкретному объекту.

POST создания объекта и добавления работ принимают необязательный workStages —
массив номеров в порядке подтверждённого набора работ. Сервер проверяет целые
положительные числа, количество элементов и диапазон stageCount. Порядок шаблона
и его версия проверяются существующим механизмом. Старые клиенты без workStages
по-прежнему работают. Новые назначения входят в аудит и проверку повторных запросов.

GET /api/upts/contracts/:contractId/works возвращает все неудалённые работы объекта
для его редактора; права проверяются через текущую принадлежность УПТС и управление
проектом. Внешние фильтры доски на список не влияют.

PUT карточки объекта принимает taskStages: {id, version, stageNumber}[]. Меняются
только указанные работы этого объекта; проверяются версии и принадлежность, номер
этапа каждой существующей работы. Изменения работ и объекта выполняются в одной
транзакции под общей блокировкой work-модуля. Изменённые работы получают новую версию
и отдельную запись журнала. Ошибки не приводят к частичному сохранению.

## Проверки

TypeScript клиента/сервера; компиляция 27 Vue-компонентов; DOM-проверки таблицы,
выделения всех/части строк, массового назначения, сохранения черновика, новых и
существующих объектов, повторных запросов, ошибок загрузки, ручных и добавляемых работ.
Интеграционные тесты API с Prisma проверили сохранение, диапазоны, повторные запросы,
конфликты версий, права, принадлежность работ, аудит, сокращение количества этапов,
независимость этапа дороги и экспорт. Установщик проверяется на исходной версии,
повторном применении, локальных независимых правках и конфликте без частичной записи.
Полная production-сборка Nuxt и визуальная проверка в браузере целевого сервера
в этой среде не выполнялись.
