# УПТС: группы доступа и версия приложения

Обновление от 03.11.2026 исправляет ограничение, которое учитывало только подразделение пользователя.

## Доступ к разделу

Активный пользователь может войти в УПТС при выполнении хотя бы одного условия:

- Он системный администратор по существующей серверной настройке `adminLogins` (обычно `NUXT_ADMIN_LOGINS`).
- Его сохранённое активное подразделение имеет ключ `upts` либо название «УПТС» / «Управление подготовки территории строительства».
- Он состоит в активной внутренней группе Space с названием «УПТС», `upts` или «Управление подготовки территории строительства».
- Его подтверждённое членство в AD связано с такой внутренней группой Space через активную импортированную группу AD.
- Он состоит в активной импортированной группе AD с одним из этих точных названий.

Регистр, лишние пробелы и нормализация Unicode учитываются. Частичные совпадения вроде «Поддержка УПТС» прав не дают. Группа AD должна быть зарегистрирована в Space; произвольные названия групп из браузера не принимаются. Для групп AD используется существующий поиск в каталоге, включая вложенные группы. При недоступном AD доменное членство не считается подтверждённым; локальное членство, подразделение и системный администратор продолжают работать.

Прямое членство в группе Space проверяется по базе при каждом запросе. Повторный вход после добавления в такую группу не нужен: заново откройте раздел через «Отделы → УПТС». Заблокированные пользователи и выключенные группы доступа не получают.

Это право входа в раздел. Видимость и редактирование отдельных проектов по-прежнему определяются владельцем, командой и настройками видимости проекта. Системный администратор не становится автоматически руководителем всех проектов. Для проекта с видимостью «Подразделение» участнику группы из другого отдела нужно отдельно выдать доступ к проекту или выбрать видимость по группе.

Та же проверка применяется в API, общих проектах и файлах, при повторной проверке проекта в транзакции и при приглашении сотрудника. Членство только в команде проекта без доступа к УПТС не открывает раздел.

## О программе

Ссылка в подвале ведёт на `/about`. Страница доступна авторизованным активным пользователям. Показывает:

- идентификатор работающего релиза `YYYYMMDDTHHMMSSZ-<12 символов Git>`;
- ревизию исходного кода;
- дату и время активации этого релиза в московском часовом поясе;
- рабочую среду или среду разработки.

Номер берётся из `SPACE_RELEASE_ID` текущего серверного процесса, дата — из `SPACE_RELEASE_INSTALLED_AT`. Переключение символьной ссылки `current` само по себе не меняет ответ старого работающего процесса. Секреты и прочие переменные окружения API не возвращает. Ответ не кэшируется.

Дата установки записывается обновлённой командой `space-release` при запуске активируемого релиза и сохраняется в конфигурации PM2 и журнале развёртывания. Обычный перезапуск сохраняет дату. Откат восстанавливает сведения предыдущего релиза вместе с его конфигурацией. Повторная явная активация через `activate` записывает новую дату активации.

У старого релиза без `SPACE_RELEASE_INSTALLED_AT` отображается «Дата установки не записана». Дата сборки из имени каталога и время запуска процесса не подставляются вместо даты установки. При запуске без `SPACE_RELEASE_ID` в разработке отображается «Локальная версия».

## Обновление серверной команды

После доставки исходников на сервер, **перед активацией** нового релиза:

```bash
sudo install -o root -g root -m 750 \
  /var/www/html/MyPlatform/deploy/releases/space-release.py \
  /usr/local/sbin/space-release
```

Далее обычные `space-release prepare`, проверка результата сборки и `activate <ID> --db-compatible`. Обновление не содержит миграций базы или новых npm-зависимостей. Не добавляйте фиктивную дату вручную в общий env-файл: её должен задавать процесс развёртывания конкретного релиза.

## Проверка после установки

1. Системный администратор без подразделения УПТС открывает раздел.
2. Обычный активный сотрудник из другой службы, добавленный в группу Space «УПТС», открывает раздел. После исключения — получает отказ при следующем запросе.
3. Пользователь без подразделения/группы/системных прав видит только предупреждение о недостаточности прав.
4. В подвале открывается «О программе», номер совпадает с активированным релизом, дата — с активацией. Обновление страницы или обычный рестарт PM2 дату не меняет.

Локально проверены TypeScript/Vue, маршруты доступа с подменёнными БД/AD, полный сценарий УПТС на временной PostgreSQL-совместимой базе PGlite (проекты, файлы, Excel, архив), работа развёртывания/отката с подменой системных команд, интерфейс Chromium в двух темах и на ширине 390 px. Реальные AD, PM2, сервер и полная production-сборка Nuxt здесь не проверялись.
