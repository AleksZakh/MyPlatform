# УПТС: компоновка нового объекта и выбор работ — 06.11.2026

Обновление поверх Space-UPTS-object-layout-20261106.

## Форма

В верхней закреплённой области: условный номер (название), кадастровый номер,
объект (автомобильная дорога), местоположение (адрес), площадь, тип, номер договора.
Эти поля удалены из содержимого вкладки, существующие значения сохраняются.
Адрес хранится в objectDetails.address; кадастровый номер и площадь продолжают
использовать sourceCadastralNumber/sourceArea. Условный номер использует прежнее
поле number, прежнее отдельное name при редактировании сохраняется.

Под вкладками закреплены даты начала и окончания работ, куратор, кадастровый
инженер, количество этапов. Кнопки сохранения находятся ниже. Прокручивается
содержимое вкладки; на низких/узких экранах закреплённые группы имеют собственную
прокрутку. Высота окна не зависит от вкладки. Поля уменьшены примерно на 14%:
обычные поля 32 px, поля этапов в таблице 21 px. Цвета используют текущую тему.
Строительный «Этап» остался в характеристиках, независимо от этапов работ.

## Создание работ

Тип определяет доступные виды работ. Можно выбрать несколько видов.
Активные шаблоны библиотеки для выбранных видов задают объединение работ.
Дедупликация выполняется по ID определения работы. Сохраняется порядок видов
из справочника и порядок работ шаблонов. Новые строки всегда выключены.
Удаление вида убирает только строки, отсутствующие во всех оставшихся видах;
включение и этапы общих строк сохраняются.

Левый флажок включает работу в создаваемый объект. Выделение строки отдельно:
клик, Shift-клик для диапазона, перетягивание левой кнопкой по строкам. Отпускание
кнопки за пределами таблицы завершает выделение. Поддержаны клавиши Space/Enter
и стрелки с Shift. Элементы управления внутри строк не начинают перетягивание.
Кнопки «Включить выделенные»/«Выключить выделенные» меняют включение диапазона.
Список в шапке столбца «Этап» сразу назначает этап выделенным строкам, не меняя
их включение. Индивидуальное поле этапа доступно для включённой работы.
Сохраняются только включённые строки. Без включённых строк создаётся пустой объект.
При уменьшении количества этапов неверные назначения нужно исправить вручную.

Тип «Иное»: названия работ вводятся вручную, затем нужные строки включаются.
Максимум 50 включённых работ за создание, как в существующем API.

Существующие объекты используют прежнюю таблицу изменения этапов. Изменение
видов в карточке не удаляет и не пересоздаёт существующие работы; новые работы
после создания добавляются через «+ Работа».

## Совместимость и проверки

objectDetails.workKindKeys хранит массив видов, workKindKey — первый вид для
совместимости. Созданная работа хранит свои исходные виды в uptsWorkMeta.
API проверяет членство работы в выбранных видах, активность, версию определения,
права, диапазон этапов и повторные запросы. Старые клиенты с одним видом и
шаблоном продолжают работать. В Excel выводятся все виды и адрес; поиск учитывает адрес.
Аудит создания объекта включает выбранные определения и назначения этапов.
Новых миграций, зависимостей и автоматических правил завершения работ нет.

Проверено: TypeScript клиента и сервера, компиляция 28 Vue-компонентов,
тест объединения библиотеки, DOM-сценарии формы (Shift/перетягивание/включение/
этапы/смена видов/ручные работы/старые данные), интеграционный API-тест на
одноразовой PostgreSQL-совместимой PGlite БД с Prisma, экспорт и аудит,
установщик (предпросмотр, применение, повтор, Git HEAD, отказ при конфликте).
Полная Nuxt production-сборка и визуальная проверка в браузере не выполнялись.
После выпуска проверьте закрепление областей на своём разрешении и обе темы.
