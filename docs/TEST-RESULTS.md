# Проверка обновления

Проверено 22 сентября 2026, в изолированном окружении.

## Сервер

41 тест прошёл: 13 проверок правил/валидации и 28 HTTP/SQL сценариев. HTTP выполняется через реальные H3 handlers и Prisma, SQL — в локальном PGlite. Используются только тестовые пользователи и ресурсы, без подключения к существующей БД или корпоративным сервисам.

Проверены прежние назначения сотрудникам/отделам, отзыв, статусы, зарезервированные административные операции, контроль версии, атомарность аудита; поиск и регистрация группы, непринятие имени из браузера, escaping LDAP, преобразование raw GUID, наследование группы через guard и отображение в матрице, отзыв и изменение членства, несовпадение AD identity, отключённые группы/ресурсы, недоступность AD без выдачи права, запрет управления обычному пользователю.

Для Kerberos проверены HTTP-коды/этапы при отсутствии proxy identity, ошибке AD, отсутствии пользователя, заблокированной локальной записи, ошибке записи session и успешном завершении с числовым user ID.

**Границы проверки:** методы каталога заменены тестовым адаптером; LDAP-фильтр вложенности и обработка raw GUID проверены, но реальная AD-репликация, леса и SPNEGO-обмен не воспроизводились. `setUserSession` в HTTP-тесте — stub с успешным/ошибочным результатом; шифрование cookie, browser IWA и nginx нужно проверить на целевом окружении. PGlite не заменяет нагрузочное тестирование PostgreSQL и конкурентных соединений.

## Вёрстка

В Chromium смонтирован полный реальный `UserDirectory.vue` с настоящим `AccessMatrix.vue` и composable. Ответы API — фикстуры, NuxtLink/Icon/UButton — небольшие компоненты-заглушки. Это существенно больше, чем проверка отдельной таблицы, но не полная сборка приложения с Nuxt UI, верхним меню и sidebar.

| Размер области | Высота сводки | Высота таблицы | Прокрутка таблицы | Прокрутка карточки |
|---|---:|---:|---:|---:|
| 1440 × 900 | 16 px | 438 px | 600 px | 0 |
| 1100 × 720 | 16 px | 240 px | 600 px | 0 |
| 390 × 844 | 56 px | 238 px | 600 px | 0 |

При прокрутке таблицы заголовок и фильтры карточки сохраняют положение. На узком экране внешний AdminCenter также прокручивается для перехода от списка пользователей к карточке. Горизонтального переполнения всего документа нет; таблица на узких экранах имеет собственную горизонтальную прокрутку. Ошибок JavaScript не обнаружено.

Отдельно в браузере смонтирована реальная страница `/admin/access` и компоненты групп. Пройден путь: выбор доменных групп → поиск AD → регистрация найденной группы → открытие матрицы → успешное назначение права. AD/API ответы в этом браузерном сценарии — фикстуры; серверные маршруты проверяются отдельно HTTP-тестами.

## Типы, схема, сборка компонентов

- Изолированный `vue-tsc` для изменённых компонентов матрицы/AdminCenter/групп и серверных сервисов/handlers: без ошибок. Nuxt auto-imports представлены декларациями; это не полный `nuxi typecheck` проекта.
- `login.vue`, страница прав, импорт группы и default layout успешно скомпилированы Vue SFC compiler. Полная типизация login.vue с Nuxt plugins не запускалась.
- Скрипт добавления схемы применён к копии актуальной схемы и повторно запущен: дублей не добавил. `prisma validate` прошёл.
- Prisma Client с новыми моделями сгенерирован. SQL новой миграции получен как diff между схемой до/после. Исполняемый fixture DDL содержит новые таблицы и связи.
- На сервер пользователя ничего не развёртывалось.

## Воспроизведение

Тесты находятся в `tests/access/`. Они требуют dependencies вашего проекта и дополнительные **тестовые** пакеты `tsx`, `@electric-sql/pglite`, `@electric-sql/pglite-socket`. Запускайте в отдельной копии/тестовом окружении с Prisma Client, сгенерированным по обновлённой схеме:

```bash
TSX_TSCONFIG_PATH=tests/access/tsconfig.json node --import tsx --test tests/access/decision.test.ts tests/access/http.test.ts
```

Тестовый код задаёт свой DATABASE_URL до импорта Prisma, не загружает `.env`, поднимает локальный PGlite и очищает его при завершении. В логе намеренно присутствует ошибка `fixture audit failure`: проверяется откат назначения при отказе аудита.
