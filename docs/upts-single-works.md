# УПТС: добавление отдельных работ — 05.11.2026

Устанавливается после `Space-UPTS-contracts-ui-20261105`.

В договоре нажмите «Добавить работы». Окно открывается в режиме «Из библиотеки»: отметьте одну или несколько активных работ типа этого договора. Они не обязаны входить в шаблон. Поиск фильтрует список, сохраняя выбор; выбранные позиции показаны отдельно и могут быть удалены из выбора. Нажмите «Добавить работу» или «Добавить работы (N)».

Другие способы:
- «По шаблону» — прежнее добавление готового набора.
- «Своя работа» — одно произвольное название для любого указанного типа договора. Запись создаётся только в договоре, библиотека и шаблоны не изменяются. Для повторного использования создайте работу в «Библиотеке работ».

Работы появляются без исполнителя и срока, с привязкой к договору и его цветом. Действующие задачи сохраняются. Осознанное повторное добавление из нового окна создаёт новые записи; повторная отправка того же запроса не дублирует сохранение.

Права не расширены: добавляет владелец/руководитель активной области договора. Сервер проверяет доступ, версию договора, тип/активность/версию каждой выбранной работы. Архивные, чужого типа и изменённые после загрузки позиции не применяются. Нельзя смешивать шаблон, выбранные работы и ручной ввод в одном запросе. Добавление задач, повышение версии договора и журнал выполняются одной транзакцией. Журнал содержит идентификаторы и версии выбранных библиотечных работ, их названия и созданные задачи.

Новых миграций и npm-зависимостей нет. Схема БД не меняется; используется существующий механизм применения работ. Предыдущие операции с шаблонами сохраняют совместимость ключей повторной отправки.

Проверено: целевая типизация Vue/TypeScript; DOM-проверки реального компонента (одна работа вне шаблона, поиск, сохранение выбора, переключение способов, состав запросов и повтор); HTTP/Prisma на временной PostgreSQL-совместимой БД PGlite (добавление одной/нескольких/произвольной работы, отказ при неверном типе/версии/архиве/дублирующемся выборе, доступ, идемпотентность, аудит, цвет, отсутствие изменения библиотеки). Существующий интеграционный сценарий договоров, шаблонов и Excel также прошёл. Полная сборка Nuxt и визуальная проверка в браузере не выполнялись.
