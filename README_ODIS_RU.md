# ОДИС — счётчики, работы сооружения и сверка персональных заданий

Обновление от 10.11.2026, поверх установленного пакета импорта работ от 09.11.2026.

## Установка

Распакуйте содержимое архива в корень проекта ~/Projects/MyPlatform с заменой перечисленных файлов. Схема Prisma и миграции в пакет не входят. Новых миграций, повторного импорта 5 821 работы или изменения базы для установки этого интерфейса не требуется.

Если проект запущен через npm run dev, перезапустите dev-сервер и обновите страницу. Для собранного приложения выполните обычную сборку npm run build и перезапустите соответствующий процесс штатным способом. Зависимости проекта не менялись.

Изменения ограничены файлами ОДИС; схема и код УПТС/лаборатории в архив не включены.

## Что изменилось в договоре

- Вкладки показывают «Всего работ» и «Всего сооружений» сразу после открытия договора. Это актуальные количества из БД, а не старые контрольные числа из миграции.
- Удалённые работы, связи и сооружения в счётчики не входят. Ошибка загрузки не подменяется нулём; предусмотрена повторная попытка.
- В «Перечне сооружений» сверху находится компактная таблица. Нажатие на строку или код ИССО выбирает сооружение; первый элемент выбирается автоматически.
- Снизу находятся паспортная строка и работы выбранного сооружения В РАМКАХ ТЕКУЩЕГО ДОГОВОРА. Выбор не показывает работы того же сооружения из других договоров.
- Строки таблиц компактные: шрифт 13 px, вертикальные отступы 3 px. Длинные названия и примечания сокращаются в строке; полный текст доступен в подсказке и карточке работы.
- Верхняя и нижняя таблицы прокручиваются отдельно; заголовки закреплены. Выбранная строка оформлена в синей гамме для обеих тем.
- Быстрое переключение сооружений не позволяет запоздавшему ответу предыдущего запроса подменить текущий список.
- Оба новых API проверяют VIEW на diagnostic.contracts. API работ также проверяет принадлежность связи договору и отсутствие удаления договора, связи, сооружения и работы.

## Что сейчас показывает нижняя таблица

Она подключена к существующей модели DiagnosticStructureWork. Доступны: шифр, историческое название задания, трудоёмкость, примечание; в карточке — критерий приёмки.

В этой модели пока нет статуса задания, раздельных дат/часов плана и факта и исполнителей. Эти значения не подставляются предположениями из hours, авторов или библиотеки. Полный состав колонок из старого интерфейса появится после согласования и миграции работ по сооружениям.

Импорт dis_dog_works добавил работы непосредственно к договорам. Он не добавлял работы по сооружениям. Поэтому нижняя таблица может быть пустой — это не ошибка загрузки. Примеры из dis_user_works в БД этим пакетом не записываются.

## Проверка после установки

1. Открыть «ДЭиБДД-2021-2228»: по завершённому импорту в нём 403 работы с договором (если с тех пор их не меняли).
2. Сверить счётчик работ с таблицей. Открыть карточку работы.
3. Перейти к сооружениям: сравнить счётчик с числом строк, выбрать разные коды ИССО.
4. Проверить компактность таблиц и выделение в светлой/тёмной теме, прокрутку и пустое состояние нижнего списка.

## dis_user_works: выполненный анализ

В присланном файле 10 записей (это примеры, не полный экспорт): 2 dog_works, 8 build_works. Значение AUTO_INCREMENT=74119 не является количеством строк.

Подробности — docs/odis-user-works/analysis-notes.md и review.html. Машинный отчёт — report.json. Все 10 примеров сопоставлены с полной выгрузкой из 5 938 работ договора и проверенным APPLY-отчётом.

Скрипт для повторения анализа, без БД:

```bash
npx tsx scripts/analyze-diagnostic-user-works.ts \
  --file ~/TMP/dis_user_works.sql \
  --contract-works ~/TMP/dis_dog_works.sql
```

Необязательный параметр --contract-report /путь/к/report.json принимает успешно завершённый APPLY-отчёт от этой же выгрузки dis_dog_works и дополняет кандидатов новыми ID. Скрипт создаёт новый каталог с report.json и review.html. Он не поддерживает APPLY, не подключается к PostgreSQL, не назначает аккаунты и не объединяет записи. History игнорируется. Требуются утилиты scripts/lib из ранее установленного пакета миграции.

## Проверки реализации

- 8 автоматических тестов: фильтры удалённых записей, ограничение работ текущим договором, вызов проверки VIEW до чтения, валидация ID, точная передача Decimal, отсутствие автоматического объединения персональных заданий, конфликты прямых ссылок, неизвестные типы и ошибочные даты.
- Строгий TypeScript для нового сервиса, типов, скрипта анализа и тестов — успешно. Prisma Client для этой проверки сгенерирован локально по текущей схеме (6.19.0), без подключения к БД.
- Три Vue-компонента скомпилированы. DOM-проверка на тестовых ответах: 403 работы, 10 сооружений, повтор загрузки счётчиков, быстрое переключение, пустое/ошибочное состояние, карточка, компактные CSS-отступы и цвета выделения обеих тем.
- API проверялся с имитацией Prisma и проверки доступа; это не интеграционный тест реальной PostgreSQL/AD. В DOM-проверке UModal заменялся тестовой оболочкой. Полная сборка Nuxt и визуальная проверка в настоящем браузере здесь не выполнены: запуск Chromium недоступен в среде.
