Space: восстановление пароля внешних пользователей и журнал удалений

УСТАНОВКА
1. Сохраните текущие изменения коммитом. Сделайте резервную копию БД перед миграцией.
2. Скопируйте app, server, shared, scripts, prisma/migrations и tests из архива
   в корень проекта, сохраняя другие файлы. Схема целиком не заменяется.
3. В корне проекта:
   node scripts/apply-password-reset-schema.mjs
   npx prisma validate
   npx prisma migrate deploy
   npx prisma generate
   npx nuxt typecheck
   node tests/password-reset.test.cjs
4. Соберите и перезапустите Space обычным для вашего сервера способом.
   Сначала миграция БД, затем запуск новой сборки: новая авторизация читает новые поля.
   Если Prisma выдаёт ошибку истории миграций/baseline, не используйте reset или
   db push --accept-data-loss. Сохраните текст ошибки для разбора.

SMTP И NGINX
Используются существующие runtimeConfig.smtp и runtimeConfig.siteUrl.
На боевом сервере siteUrl должен быть полным HTTPS URL Space.
Письмо отправляется существующим nodemailer; новых npm-зависимостей нет.
На nginx эти адреса должны быть доступны без Basic/Kerberos challenge:
  GET /forgot-password
  GET /reset-password
  POST /api/auth/forgot-password
  POST /api/auth/reset-password
Остальные правила nginx не меняйте. Если на этих адресах nginx выдаёт
401 с WWW-Authenticate: Negotiate, нужны исключения для этих конкретных маршрутов
по образцу вашего работающего /api/auth/external-login.

ВОССТАНОВЛЕНИЕ
На вкладке входа внешнего пользователя появилась ссылка «Забыли пароль?».
Пользователь указывает email, получает одноразовую ссылку, задаёт новый пароль
и возвращается ко входу. Автоматического входа после сброса нет.

- Только EXTERNAL со статусом ACTIVE. Доменный пароль через Space не меняется.
- Ссылка действует 30 минут. В БД хранится SHA-256 токена, а не токен.
- Токен передаётся в #fragment, затем удаляется из адресной строки браузера.
  Если перезагрузить форму после открытия, нужно снова перейти по ссылке из письма.
- Пароль 12–128 символов, как в существующей активации. Пароль хэшируется scrypt.
- Погашение токена, смена пароля, отзыв сессий и аудит атомарны.
- Повторный запрос ссылки аннулирует предыдущую после успешного выпуска новой.
- Текущий пароль сохраняется до успешного сброса.
- Заблокированная учётная запись не активируется восстановлением.
- Прежние внешние сессии отзываются при следующем запросе к Space.
  Уже выполняющийся запрос не прерывается. Старые cookie без версии считаются
  версией 0 и продолжают работать до первого сброса пароля.
- Формат cookie дополняется externalSessionVersion. Для DOMAIN изменений нет.
- Ответ запроса письма одинаков для существующего и неизвестного email.
  Доставка синхронная; одинаковое время ответа для этих случаев не гарантируется.
- Ограничения на все процессы Space общие через PostgreSQL:
  3 запроса в час на email; не чаще 1 письма в минуту на учётную запись;
  100 запросов восстановления в час на всю систему;
  1000 попыток применения ссылки за 15 минут на всю систему.
  Глобальные лимиты выбраны для небольшой корпоративной системы; при необходимости
  измените явные значения в password-reset.service.ts.
- Ошибка SMTP записывается в системный аудит RESET_MAIL/FAILED. Токен не выводится
  в журнал приложения и аннулируется при неудачной отправке.

ЖУРНАЛ
В лабораторном журнале добавлена отдельная таблица «Удаления» с пагинацией:
дата, сущность и ID, исполнитель, причина/описание.
Источник — существующий AuditLog, а не действующие записи реестра.
Просмотр требует lab.event-journal → VIEW. Системный журнал продолжает работать.
Таблица включает успешные удаления реестра и справочников с зарегистрированными
ключами lab.* из комплекта. Она не создаёт события задним числом и не исправляет
сторонние обработчики, если они не записывают аудит.
У одного удаления реестра может быть три события: отбор, поступление, протокол.
Повторный DELETE уже удалённой записи не создаёт нового успешного удаления.
Обычные фильтры лабораторного журнала применяются к прежнему списку; таблица
удалений отдельно обозначена и обновляется своей кнопкой.

ПРОВЕРКА НА СТЕНДЕ
1. Удалите тестовую запись с причиной; проверьте таблицу «Удаления» и системный
   журнал. Исполнитель, ID и причина должны совпасть.
2. Запросите восстановление для активного внешнего пользователя и дождитесь письма.
3. Откройте ссылку. Разные пароли в двух полях должны быть отклонены.
4. Сохраните пароль; старый пароль не подходит, новый подходит.
5. В другом браузере со старой сессией выполните защищённый запрос: должен быть 401
   или переход на страницу входа. Войдите новым паролем.
6. Откройте использованную ссылку ещё раз: повторный сброс запрещён.
7. Проверьте ссылку старше 30 минут, доменный email, неизвестный email и
   заблокированного внешнего пользователя: восстановления быть не должно.
8. Проверьте отсутствие токенов и паролей в журнале аудита.

ЧТО ПРОВЕРЕНО ЗДЕСЬ
- Prisma validate и генерация клиента по дополненной присланной схеме.
- Сравнение миграции со схемой: только новые поля User и таблица лимитов.
- Серверные типы на Prisma 6.19.3 и доступных исходниках.
  Для отсутствующего в частичном окружении nodemailer использован проверочный
  контракт типов; проверка вашего полного проекта всё равно необходима.
- Компиляция пяти Vue SFC.
- 16 тестов с имитацией БД и SMTP, включая атомарность и отзыв сессий.
Живая БД, ваш SMTP и браузерный вход здесь не запускались.
