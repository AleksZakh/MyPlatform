Space — мягкое удаление, версия 1

УСТАНОВКА
1. Сделайте коммит текущего состояния проекта.
2. Скопируйте каталоги app, server, scripts, tests из архива в корень проекта
   с заменой одноимённых файлов. Не удаляйте остальные файлы проекта.
3. Из корня проекта выполните:
   node scripts/apply-delete-ui.mjs
   Скрипт точечно обновляет ObjectsForm.vue, создаёт резервную копию и
   отказывается менять файл, если его структура отличается от проверенной.
   Если он отказался — пришлите актуальный ObjectsForm.vue; не обходите проверку.
4. Проверка:
   npx nuxt typecheck
   node --test tests/deletion.test.cjs
5. Проверьте в dev, затем выполните обычную сборку и перезапуск Space.
   Перед перезапуском дождитесь завершения текущего запроса миграции.
Миграция Prisma и повторный seed не нужны. Комплект не выдаёт никому новых прав.

КЛЮЧИ МАТРИЦЫ
Реестр / отбор проб: lab.sampling-tests → DELETE
Материалы: lab.materials → DELETE
Производители: lab.manufacturers → DELETE
Объекты: lab.test-objects → DELETE
Места отбора: lab.test-locations → DELETE
Отдельные несвязанные поступления: lab.receipt-materials → DELETE
Отдельные несвязанные протоколы: lab.test-protocols → DELETE
Используются существующие requirePermission и GET /api/access/check.
Правила вычисления эффективных прав, включая существующие правила системного
администратора, не меняются. UPDATE и авторство не заменяют DELETE.
Проверки UI через /api/access/check при отказе могут создавать существующие
события ACCESS/DENIED — это поведение вашего обработчика проверки доступа.

ПОВЕДЕНИЕ
- UI проверяет DELETE при открытии; перед удалением проверяет повторно.
  После выдачи нового права обновите страницу, чтобы активировать кнопку.
- Запрашивается обязательная причина через стандартное окно ввода браузера.
  Отмена/пустая причина не отправляют DELETE. Сервер отдельно проверяет причину.
- DELETE принимает JSON: { "reason": "Ошибочно созданная запись" }.
- /api/incoming-control/:id и /api/lab/sampling-test/:id теперь удаляют один
  и тот же агрегат SamplingTest. Старое физическое удаление AEng заменено.
  ID берётся из текущего реестра SamplingTest, НЕ из старой таблицы AEng.
- В одной транзакции помечаются удалёнными SamplingTest, его ReceiptMaterial
  и TestProtocol, если он есть. Это удаление целого реестрового агрегата по
  DELETE lab.sampling-tests; дополнительные DELETE для его частей не нужны.
- Справочники и файлы не удаляются. Пути, ID и связи сохраняются.
- Отдельное удаление связанного поступления/протокола запрещено (409),
  даже если родитель уже мягко удалён. Автоматического разрыва связей нет.
- Аудит хранит причину, пользователя и изменение полей удаления.
  Для агрегата создаются события по каждой фактически изменённой сущности.
- Повторный DELETE уже удалённого элемента успешен, не меняет дату и аудит.
- Удаление справочника с действующими ссылками запрещено. Существующие
  проверки использования и их счётчики сохранены.
- Возраст записи не ограничивает DELETE. Правило 30 минут для UPDATE не меняется.
- Восстановление удалённых записей и физическое удаление файлов не реализуются
  этим комплектом. ПЛП и другие не присланные справочники не заменяются.

ПРОВЕРКА НА ВАШЕМ СТЕНДЕ
1. Пользователь без DELETE: кнопка недоступна; прямой DELETE возвращает 403.
2. Пользователь с DELETE: отмена/пустая причина не удаляет запись.
3. Удалите тестовую запись старше 30 минут с заполненными тремя документами.
   Она исчезает из действующего реестра. В БД три сущности помечены удалёнными,
   пути и файлы сохранены. В журнале видны причина и исполнитель.
4. Повторите DELETE того же ID с причиной: alreadyDeleted=true, нового аудита нет.
5. Попытайтесь удалить материал/изготовителя/место, используемые другой
   действующей записью: 409 с объяснением, справочник не изменён.
6. Удалите неиспользуемое значение справочника: оно скрыто, аудит записан.
7. Отзовите DELETE после открытия формы: сервер запрещает новый запрос.
8. Проверьте удаление последней строки страницы реестра и его фильтры/экспорт.

ВЫПОЛНЕННЫЕ ПРОВЕРКИ
Серверный TypeScript проверен на предоставленной схеме и доступных зависимостях.
Vue compiler-sfc компилирует изменённые формы и точечно обновлённую ObjectsForm.
11 автоматических тестов сервиса проходят с имитацией БД/транзакций.
Живые PostgreSQL, браузерная авторизация и полная сборка вашего проекта
здесь не запускались. Проверка npx nuxt typecheck в полном проекте обязательна.
