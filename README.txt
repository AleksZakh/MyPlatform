Восстановление выбора и создания производителя в форме реестра

Скопируйте app и server из архива в корень проекта с заменой четырёх файлов:
  app/components/lab/createModal.vue
  server/api/incoming-control/index.post.ts
  server/api/incoming-control/[id].put.ts
  server/services/lab/incoming-control-manufacturer.service.ts

Общий сервис обязателен: его вызывают оба эндпоинта.
Схема БД и назначения прав не изменяются. Миграция Prisma не нужна.

Поведение:
- Поле предприятия-изготовителя — ввод текста с подсказками (UInput + datalist).
- Поиск идёт по всему загруженному списку производителей, затем выводится до 50 подсказок.
- Можно выбрать существующее название или ввести новое.
- Новый производитель создаётся только при сохранении записи, в той же транзакции,
  с проверкой lab.manufacturers → CREATE и записью в аудит.
- Выбор существующего производителя не требует CREATE справочника.
- Производитель, отличающийся только регистром, повторно не создаётся при единственном совпадении.
- Мягко удалённый производитель автоматически не восстанавливается.
- Правила дат, права реестра и окно редактирования сохранены из присланных файлов.

После замены:
  npx nuxt typecheck
Перезапустите dev-сервер; для production выполните обычную сборку и перезапуск.

Проверка:
1. Создание записи: ввести часть названия, выбрать подсказку, сохранить.
2. Создание записи: ввести новое название, сохранить, проверить справочник.
3. Редактирование доступной для изменения записи: повторить оба варианта.
4. Без CREATE производителя новое название должно приводить к 403,
   а существующее — сохраняться при наличии необходимых прав на реестр.

Типы общего серверного сервиса и компиляция Vue проверены.
Полная проверка эндпоинтов в частичном окружении блокируется отсутствующим
пакетом zod, который используется вашим существующим сервисом валидации.
Поэтому выполните npx nuxt typecheck в полном проекте.
Сохранение на вашей БД здесь не выполнялось.
