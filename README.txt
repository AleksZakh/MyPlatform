Space — компания из Active Directory

Замените два файла в проекте на компьютере разработки, проверьте git diff, сделайте коммит и отправьте его в Git.
На сервере: git pull --ff-only, space-release prepare, затем space-release activate НОВЫЙ_RELEASE_ID --db-compatible.
Миграция БД и изменение зависимостей для этого исправления не нужны: поле organization уже существует.

В запрос AD добавлено company, в нормализованные данные — company, при создании и синхронизации DOMAIN-пользователя значение сохраняется в organization. Изменение компании учитывается при проверке необходимости UPDATE.
После развёртывания выйдите из Space и войдите заново через Kerberos или доменный пароль: именно при входе выполняется синхронизация локальной учётной записи. Перезагрузка страницы профиля без нового входа сама по себе данные AD не запрашивает.
Обновление AD-кэша также получит company, но не означает массовое обновление organization всех существующих учёток в БД.
Если company в AD не заполнено, организация останется не указанной. Для старой записи кэша, где атрибут company отсутствует вообще, существующая организация не затирается.
Пользовательские дополнительные данные, фото и внешние учётные записи не меняются.
