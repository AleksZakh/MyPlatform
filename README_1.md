# Space v4 — отделы из department и внутренние группы

Пакет поверх установленных v2 + v3. Файлы перечислены в FILES.txt. Матрица сохраняет отложенное применение, полные права и увеличенный шрифт.

## Установка

1. Скопируйте app/, server/, shared/, prisma/migrations/ из архива с сохранением путей. Перезапускайте приложение только после миграции и генерации клиента.
2. Для обычной однофайловой схемы выполните из корня проекта:

   python3 scripts/add-space-groups.py prisma/schema.prisma
   npx prisma validate
   npx prisma generate
   npx prisma migrate deploy

   Скопируйте также scripts/ и schema-additions.txt для работы скрипта. Скрипт сохраняет исходную схему в .bak, добавляет только четыре новые модели и три обратные связи. Повторный запуск не создаёт дубли. Для схемы, разбитой по файлам, внесите schema-additions.txt в соответствующие модели вручную — скрипт рассчитан на один файл.

3. Пересоберите и перезапустите приложение обычным способом.

В схеме уже должны быть DirectoryDepartmentMapping и DomainGroup из предыдущих этапов. Не заменяйте всю бизнес-схему новой. schema-additions.txt — инструкция, а не дополнительный .prisma-файл. Миграция добавляет только четыре таблицы SpaceGroup; существующие назначения и бизнес-таблицы не удаляет. Для базы без согласованной истории Prisma migrations сначала согласуйте baseline; не используйте migrate reset.

## Отделы

Откройте /admin/structure → «Отделы из AD». Эта страница также доступна по ссылке из управления правами и из карточки сопоставления подразделения.

1. Обновите кэш AD штатной кнопкой «Обновить AD» в AdminCenter, если требуется свежая информация.
2. Выберите название department. Выберите существующий отдел Space либо оставьте автоматический выбор: сохранённое сопоставление → одноимённый отдел → создание отдела.
3. Нажмите «Предпросмотр», проверьте переводы и пропуски, затем «Применить синхронизацию».
4. Перейдите в /admin/access, выберите подразделение и назначьте права.

Синхронизация работает по одному выбранному названию department. Разные названия можно явно связать с одним отделом Space. Пробелы и Unicode нормализуются, похожие названия не объединяются автоматически. ID отдела и ранее назначенные права сохраняются. Пустые/исчезнувшие значения не удаляют отделы и не снимают связи автоматически. Переводы существующих пользователей происходят только через предпросмотр/применение, не при каждом обновлении кэша.

Для переноса зарегистрированных пользователей требуется совпадение objectGUID: привязка только по похожему имени или email не выполняется. Пользователь только в кэше, без учётной записи Space, попадает в пропуски. После первого доменного входа новая запись получает отдел по подтверждённому сопоставлению. Существующие записи, в том числе без GUID, автоматически при входе не переводятся; после восстановления связи нужно повторить синхронизацию.

Кэш, сопоставление и БД включены в версию предпросмотра. При изменении данных старый план отклоняется. Изменение departmentId, создание отдела/сопоставления и аудит сохраняются транзакционно.

## Внутренние группы Space

/admin/structure → «Группы Space» → «Создать группу». Задайте название, добавьте зарегистрированных пользователей и/или импортированные группы AD, сохраните состав. Для добавления новой группы AD есть переход к прежнему импорту.

Права назначаются в /admin/access → «Группе Space» через ту же матрицу. Участие во многих группах разрешено. Вложенные группы Space в первой версии не предусмотрены. Включение группы AD означает живую ссылку, а не копирование участников; вложенное членство AD учитывается существующим LDAP-механизмом.

Отключённая группа Space или AD не даёт прав. При недоступности AD права через AD-состав не подтверждаются; личные права, отдел и прямое участие в группе Space продолжают проверяться независимо. Состав групп и разрешения читаются при запросе, повторный вход для отзыва не нужен. Матрица показывает «Группы Space» как отдельный источник.

Поиск показывает до 50 вариантов — уточняйте строку, если результатов больше. Состав группы ограничен 1000 прямых пользователей и 1000 групп AD. Изменения состава сохраняются отдельной кнопкой, при переключении групп есть предупреждение о сбросе черновика. Перед переходом на другую страницу сохраните состав.

Управлять структурой и назначениями сейчас может только системный администратор. Прямые права групп AD из v2 не удаляются: если их раньше выдавали, они продолжают действовать независимо от групп Space.

## Проверка и следующий шаг

44 теста на изолированной PostgreSQL-совместимой базе PGlite прошли: наследование и отзыв, отключения, ограничения администратора, AD-недоступность, источники в матрице, версии/конфликты, аудит, повторная синхронизация без дублей, первый вход с сопоставлением. Проверены TypeScript/Vue, SQL-миграция и браузерный сценарий предпросмотра/применения и создания группы с пользователем и группой AD, включая мобильную ширину.

Ваша реальная БД и AD этими тестами не затрагивались. Полная production-сборка проекта здесь не запускалась. Следующий шаг — один тестовый отдел, один сотрудник и одна группа Space: выдать VIEW, проверить реальный ресурс, отозвать право и проверить журнал.

Связь CREATE/UPDATE/DELETE с VIEW пока остаётся правилом интерфейса из v3; серверные действия проверяются независимо. Доработку единой серверной политики рассмотрим вместе с проверкой ресурсов.

Будущий этап «Карточка и страница отдела с ресурсами, службами и сервисами» записан в docs/ROADMAP.md.
