# Space: WebSocket и пользователи online

Первая реализация присутствия, основа для будущего чата. Сообщения чата пока не реализованы.

## Поведение

Все авторизованные пользователи подключаются автоматически и видят страницу /online
(пункт «Пользователи online» в навигации). Несколько вкладок/устройств объединяются.
Имя/логин берутся только из проверенной сервером сессии. Пять минут без взаимодействия —
«Отошёл». Закрытие последней вкладки удаляет пользователя; обрыв сети определяется
ping/pong приблизительно за 25–50 секунд. Offline-пользователи не показаны.
При потере сервиса клиент очищает список и показывает состояние подключения, а не устаревший online.

Nuxt выпускает подписанный билет на 120 секунд. Билет передаётся первым сообщением,
не в URL; клиент обновляет его каждые 60 секунд через действующую сессию Nuxt.
Неавторизованный сокет не получает списка пользователей. Origin проверяется по точному списку.
Выход из приложения закрывает соединение в этой вкладке. В других вкладках, если
состояние сессии не обновилось сразу, доступ прекращается при следующем продлении.
Принудительный отзыв внешней сессии учитывается существующим middleware Nuxt.
Мгновенного централизованного отзыва доменных cookie эта реализация не добавляет.

Список хранится в памяти одного процесса space-ws. История посещений и lastSeen в БД
пока не сохраняются. После перезапуска список восстанавливается переподключениями.
Использовать ровно один экземпляр space-ws; для нескольких серверов потребуется общее хранилище.

## Перед установкой

Сохраните резервную копию заменяемых файлов и текущей .output, вне каталога проекта.
Архив содержит только изменения. package.json из архива НЕ заменяет ваш текущий:
измените только две команды scripts, приведённые ниже. Новых зависимостей не требуется:
используются уже имеющиеся ws, TypeScript и @types/ws (проверьте npm ls @types/ws).
Если @types/ws отсутствует, установите npm install --save-dev @types/ws и сохраните lockfile.

Новые server/api/realtime и app/plugins нужно включить в сборку Nuxt.
Файлы server/realtime/token.ts и server/websocket.ts нужны также для отдельной сборки WS.

## Сервер

1. В package.json измените:

```json
"build:ws": "tsc -p server/tsconfig.websocket.json",
"start:ws": "node dist-server/websocket.js"
```

2. В /etc/space/space.env добавьте WS_AUTH_SECRET (отдельный от NUXT_SESSION_PASSWORD).
Сгенерировать и дописать его без вывода в терминал можно следующей командой root.
Выполнить один раз; если переменная уже существует, используйте существующее значение:

```bash
python3 - <<'PY'
from pathlib import Path
import secrets
p = Path('/etc/space/space.env')
s = p.read_text()
if any(line.strip().startswith('WS_AUTH_SECRET=') for line in s.splitlines()):
    raise SystemExit('WS_AUTH_SECRET уже задан; файл не изменён')
with p.open('a') as f:
    f.write('\nWS_AUTH_SECRET=' + secrets.token_hex(32) + '\n')
PY
```

Добавьте через редактор (одну строку, без дубликатов):

```dotenv
WS_ALLOWED_ORIGINS=https://space.avtodor-eng.ru
```

Оба процесса читают один /etc/space/space.env. Сохраните владельца root:space и права 640.
NUXT_SESSION_PASSWORD не меняйте. Не присылайте содержимое env в переписку.

3. В каталоге проекта соберите:

```bash
cd /var/www/html/MyPlatform
npm run build:ws
npm run build
node --test tests/realtime/presence.test.mjs
```

Сборку выполняйте обычным пользователем развёртывания с нужным окружением проекта.
Не запускайте второй Nuxt параллельно: в нём есть фоновые задания.
Рекомендуется собрать в отдельной копии проекта и заменить .output в окно обновления:
сборка поверх работающей .output может затронуть обслуживание запросов.

4. Установите отдельный конфиг PM2 и запустите WebSocket (root):

```bash
install -o root -g space -m 640 \
  /var/www/html/MyPlatform/deploy/websocket/ecosystem.websocket.cjs \
  /etc/space/ecosystem.websocket.cjs
cd /home/space
sudo -u space -H /usr/local/bin/pm2 start /etc/space/ecosystem.websocket.cjs --only space-ws
curl --fail http://127.0.0.1:5050/health
sudo -u space -H /usr/local/bin/pm2 logs space-ws --lines 40 --nostream
```

5. В действующий HTTPS server {} nginx добавьте location из nginx-location.conf.
Существующие Kerberos, /files и proxy приложения не меняйте.
Порт 5050 не открывайте в firewall: он слушает только loopback.

```bash
nginx -t
```

Только если проверка успешна:

```bash
systemctl reload nginx
```

6. После размещения новой .output перезапустите только Nuxt:

```bash
cd /home/space
sudo -u space -H /usr/local/bin/pm2 restart space-app
sudo -u space -H /usr/local/bin/pm2 logs space-app --lines 40 --nostream
```

Это единственный необходимый короткий перерыв приложения (один fork-процесс).
Сам запуск space-ws и reload nginx остановки Space не требуют.

7. Проверьте в браузере вход и /online: вы видны один раз; вторая вкладка не удваивает
счётчик; другой пользователь виден отдельно; закрытие последней вкладки убирает его.
Через пять минут без действий — «Отошёл»; движение мышью/клавиша возвращает «В сети».
В DevTools Network /ws должен иметь 101, ticket — 200. Без входа ticket возвращает 401.
Проверьте выход, повторный вход, прерывание сети и перезапуск только space-ws.

После успешной проверки:

```bash
sudo -u space -H /usr/local/bin/pm2 save
```

Ранее созданный pm2-space.service восстанавливает сохранённый список, теперь из двух
процессов. Перезапуск всей службы для добавления WS не нужен.

## Разработка: npm run dev:all

В локальном .env задайте свой WS_AUTH_SECRET и точные origins адресов, по которым
открываете Nuxt, например WS_ALLOWED_ORIGINS=https://localhost:3000.
Скрипт dev:ws должен читать .env:

```json
"dev:ws": "node --env-file=.env --import tsx server/websocket.ts"
```

Клиент использует /ws на том же origin, что и Nuxt. Для локального HTTPS нужен
локальный reverse proxy с маршрутом /ws на 127.0.0.1:5050 (по аналогии с nginx выше).
Прежний ws://localhost:5050 из HTTPS-страницы использовать нельзя.
Одного npm run dev:all без локального прокси недостаточно для нового подключения.
Конфигурация локального HTTPS в этот production-пакет не входит; на сервере маршрут
обеспечивает приведённый nginx location. Не используйте Nitro devProxy как замену:
в установленной версии его обработчик WebSocket upgrade уходит в Nitro worker.

## Проверки и ограничения

Автоматические проверки: подпись и срок билета; отказ неверному Origin и неверному билету;
отсутствие доступа до авторизации; объединение вкладок; сохранение пользователя после
закрытия одной вкладки; запрет смены личности внутри соединения. Сборка WS и vue-tsc.
Полная интеграция с вашей AD, nginx и настоящими cookie проверяется на сервере после установки.

Откат: восстановить прежние .output и изменённые исходники, restart space-app;
pm2 delete space-ws под space, затем pm2 save. Дополнительный location /ws можно убрать
и после nginx -t выполнить reload. База данных не изменяется.
