# Space: исправление HTTP 400 при отправке приглашения

Устанавливается поверх Space-chat-ad-search-fix-20261012.zip.
Причина: схема запроса требовала UUID, тогда как текущий AD-адаптер возвращает строковые идентификаторы других форматов. Теперь поле принимается как ограниченная строка без пробелов/управляющих символов. Это только исправление формата входного запроса: проверка логина, идентификатора и доступности по актуальному ответу AD сохранена.

Текст ошибки приглашения больше не сообщает об ограничении сообщения в 4000 символов.

Распакуйте в исходный проект, добавьте все файлы из архива в Git (в том числе новый server/services/chat/invitation-input.ts), создайте коммит и отправьте в GitHub. На сервере:

```
cd /var/www/html/MyPlatform
git pull --ff-only
space-release prepare
```

После READY подставьте новый ID:

```
space-release db-status RELEASE_ID
space-release activate RELEASE_ID --db-compatible
space-release status
```

Новых миграций нет. После активации обновите страницу, заново найдите сотрудника и отправьте приглашение. Предыдущий запрос HTTP 400 не дошёл до SMTP и не занял лимит отправки.

Проверки: тест валидации с фактически полученным форматом идентификатора и некорректными запросами; интеграционный тест создания ожидающей записи, отправки и активации на изолированной PGlite с заглушками LDAP/SMTP; vue-tsc -b. Реальную доставку корпоративной почты требуется проверить на сервере.
