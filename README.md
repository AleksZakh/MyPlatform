# Экспорт реестра входного контроля Space — v1

## Установка

Архив устанавливается поверх версии с быстрым поиском, которую вы уже проверили командой `npx nuxt typecheck`.

1. Закоммитьте текущие изменения. Скопируйте папки `app`, `server`, `shared` в корень проекта, сохранив структуру.
2. Установите зависимости в корне проекта:

```bash
npm install --save-exact exceljs@4.4.0 archiver@7.0.1
npm install --save-dev --save-exact @types/archiver@6.0.3
npx nuxt typecheck
```

Не заменяйте весь package.json. Изменения package.json и package-lock.json, сделанные npm, включите в коммит.

3. Укажите каталоги в окружении ПРОЦЕССА Space:

```dotenv
LAB_FILES_ROOT=/var/www/uploads-storage/files
LAB_EXPORT_ROOT=/var/www/uploads-storage/exports
```

`LAB_FILES_ROOT` — существующее хранилище документов. В него экспорт ничего не записывает и ничего из него не удаляет.

`LAB_EXPORT_ROOT` — отдельный непубличный каталог для заданий, снимков и архивов. Процесс Space должен иметь право создавать в нём файлы. При локальной разработке задайте доступный локальный каталог вместо `/var/www/...`. В собранном приложении переменные нужно передать через ваш менеджер процессов; одного изменения `.env` без перезапуска может быть недостаточно.

Не размещайте каталог экспорта внутри `/files/`, `public/` или каталога, который nginx отдаёт статически. Прямой nginx location для архивов не нужен: скачивание идёт через защищённый API.

4. После проверки выполните штатные `npm run build` и перезапуск Space. Сейчас у вас идёт миграция: перезапуск согласуйте с остановкой миграционного скрипта между запросами, сохранив его журналы.
5. Начните с фильтра, возвращающего 2–5 записей. Проверьте ZIP и ссылки в Excel после полной распаковки архива.

Миграций Prisma и изменений схемы БД нет. Дополнительный cron не требуется.

## Что заменяется

- `app/components/lab/ExportRecordsModal.vue` — рабочая форма вместо уведомления-заглушки.
- `app/components/lab/incominginspection.vue` — передаёт текущие видимые столбцы в их порядке; содержит уже установленный быстрый поиск.
- `server/api/incoming-control/index.get.ts` — использует общую функцию фильтрации. Быстрый поиск продолжает применяться к таблице.

Остальные файлы новые. Ранее установленные `useIncomingControlRegistryLoader.ts` и `incoming-control-search.ts` оставьте на месте.

## Как пользоваться

1. Настройте фильтр таблицы.
2. Откройте экспорт и выберите любое сочетание: реестр Excel, акты отбора, паспорта, протоколы. По умолчанию отмечен только реестр.
3. Для Excel выберите «Как в таблице» или «Все поля реестра».
4. Нажмите «Подготовить выгрузку». Сервер в фоне фиксирует значения записей и пути документов, считает доступные документы и их объём.
5. После подготовки проверьте количество записей и документов. Размер указан для документов до упаковки, без Excel и текстового отчёта.
6. Без фильтра будет предупреждение о выгрузке всего реестра. «Выгрузить всё» доступно только после отдельного подтверждающего флажка. Эта проверка есть и на сервере; она действует для Excel без файлов и для файлов без Excel.
7. Подтвердите сборку. Окно можно закрыть: задача продолжает работать. Чтобы вернуться, откройте экспорт и выберите задание в «Мои выгрузки».
8. Скачайте готовый ZIP. Есть отмена подготовки/сборки; отменённая задача не публикует частичный ZIP.

Быстрый поиск, страница таблицы и выделенная строка НЕ участвуют в экспорте. Используется только фильтр из `lab_reestrTable_filter`. Неизвестные поля запроса, например `search`, не включаются в условие отбора.

Реестр отсортирован по дате создания и ID по убыванию, как текущая основная таблица. Все отфильтрованные записи выгружаются без ограничения размером страницы.

## Содержимое ZIP

- `Реестр.xlsx` — только если выбран «Реестр»; листы «Реестр» и «Документы».
- `Документы/<ID Space>/Акт_<номер>.<расширение>`.
- `Документы/<ID Space>/Паспорт_<номер>.<расширение>`.
- `Документы/<ID Space>/Протокол_<номер>.<расширение>`.
- `Отчёт-экспорта.txt` — всегда, в том числе без Excel. Содержит фильтры, время фиксации состава, количества и результаты по выбранным документам.

ID в папке предотвращает конфликт одинаковых номеров документов у разных записей. Неподходящие для файловой системы символы номера заменяются подчёркиванием. Расширения исходных файлов сохраняются; конвертации нет.

Даты в Excel являются датами с форматом `dd.mm.yyyy`. Номера — текст, ведущие нули сохраняются. Ввод пользователя не интерпретируется как формулы. Первая строка закреплена, заголовки оформлены, автофильтр включён. Ссылки относительные: распакуйте ZIP полностью, сохранив соседство Excel и папки «Документы».

Ссылки создаются только на действительно включённые файлы. Если тип файлов не выбран, в соответствующем столбце реестра остаётся имя прикреплённого файла без ссылки; лист «Документы» описывает только выбранные типы. Неизвестные идентификаторы видимых столбцов не выгружаются молча: сервер предлагает выбрать все поля.

## Миграция, недоступные файлы и перезапуск

Снимок БД фиксируется во время подготовки состава, а не в момент открытия формы. Пути новых документов, прикреплённых миграцией после снимка, попадут только в следующую выгрузку.

Для выбранных документов сохраняются размер, время изменения, устройство и inode. Перед копированием и после него они проверяются. Изменившийся, отсутствующий, недоступный файл или небезопасный путь пропускается с записью в отчёт. Отсутствие прикрепления тоже отражается отдельно. Предупреждения относятся к документам, а не к числу уникальных записей.

Байты каждого файла фиксируются при его копировании в архив. Это не резервная копия файловой системы на один момент времени. Существующие документы Space предполагаются неизменяемыми файлами; новые загрузки получают новые имена.

При ошибке записи архива, нехватке диска или повреждении потока задача заканчивается ошибкой, незавершённый ZIP не выдаётся. Подробная причина записывается в серверный журнал с префиксом `[lab-export]` и идентификатором задачи.

Задания и снимки хранятся на диске, поэтому список не исчезает при перезапуске. Уже готовые архивы остаются доступны. Сборка, прерванная перезапуском, отмечается ошибкой с предложением создать новую выгрузку; автоматического продолжения частично записанного ZIP нет. Готовые архивы удаляются спустя сутки после завершения; ожидающие подтверждения и прочие задания — спустя сутки после создания. Проверка срока при скачивании действует независимо от физической очистки.

## Фоновый процесс и нагрузка

Реализация предназначена для постоянно работающего Node/Nuxt-сервера с локальным постоянным диском, как текущий Space. Не предназначена для serverless и нескольких серверов с несогласованными дисками.

Nitro-плагин проверяет очередь каждые 2 секунды. Тяжёлые задачи выполняются последовательно. В PM2-кластере обработчик запускается только на `NODE_APP_INSTANCE=0`. Через `LAB_EXPORT_WORKER=0` его можно отключить для конкретного процесса; хотя бы один процесс должен обслуживать очередь. Произвольный многопроцессный/многосерверный запуск сначала требует проверки вашей схемы развёртывания.

ZIP и Excel пишутся потоково. Файлы не собираются целиком в оперативной памяти; используется один временный файл. Значения записей фиксируются одним ограниченным по времени чтением БД и сохраняются JSON-снимком. DB-транзакция заканчивается до работы с файлами. ZIP хранит PDF/JPEG без повторного сжатия, чтобы снизить нагрузку на CPU; ZIP64 поддерживает большие архивы.

Для планирования места нужны сумма размеров документов, место под самый большой временный документ, Excel и служебные данные. Есть предварительная проверка свободного места, однако миграция или другие процессы могут занять его позднее; ошибка диска обрабатывается отдельно.

На одного пользователя разрешены две незавершённые задачи. Повтор POST с тем же идентификатором возвращает прежнюю задачу. Повторное подтверждение не создаёт второй архив.

## Доступ и аудит

Создание, просмотр состояния, подтверждение, отмена и скачивание требуют актуального `VIEW` для `lab.sampling-tests`, как реестр. Каждое задание доступно только своему владельцу. Отозванное право блокирует последующее скачивание. Отдельное право EXPORT в этой версии не добавляется.

Изменяющие запросы требуют собственного заголовка и проверяют Origin. В nginx должен сохраняться исходный Host запроса, как для остальных API Space. Сами документы доступны работнику экспорта только внутри LAB_FILES_ROOT; внешние URL и выходы за пределы каталога не скачиваются.

В журнал событий записываются `EXPORT_PREPARE`, `EXPORT_START`, `EXPORT_CANCEL`, `EXPORT_DOWNLOAD`. Итоговые статусы и предупреждения находятся в списке задач и отчёте архива.

## Проверено перед передачей

- Проверка типов серверных файлов по доступной схеме Prisma и компиляция обоих Vue-компонентов.
- Фактическая сборка и чтение ZIP/XLSX с тестовыми документами: даты, начальные нули, строка `=SUM(1,2)` остаётся текстом, относительные ссылки присутствуют.
- Снимок не меняется при последующем изменении исходной записи.
- Выгрузка только документов не содержит Excel.
- Пустой выбор отклоняется; весь реестр требует подтверждения на сервере.
- Изоляция владельцев, проверка VIEW и Origin, запрет внешних путей и симлинка за пределы хранилища.
- Повторный запрос, пропущенный документ, отмена до запуска и во время сборки, незавершённая работа после перезапуска.

База данных в тестах имитировалась, работа на вашем полном Nuxt-проекте и нагрузка на боевом сервере ещё не проверены. После установки обязательно запустите typecheck и сделайте маленькую пробную выгрузку. Открытие относительных ссылок необходимо проверить в используемой у вас версии Excel.
