# Связь поступлений с sampling.csv — v3

Патч поверх модуля импорта материалов v1/v2. Замените три файла:
- scripts/import-files/import-receipts.ts;
- server/services/lab/receipt-migration.service.ts;
- server/api/lab/receipt-material/migration/upload.post.ts.

Сначала разверните серверные изменения: npx nuxt typecheck, обычная сборка
и перезапуск Space. Затем запускайте обновлённый клиент. Схема БД и зависимости
не меняются. Маршруты summary/detail/verify автоматически используют расширенный DTO.
На старом сервере клиент остановится с SPACE_VERSION вместо ложных несовпадений.

## Источники

В одной папке находятся receivedMaterials.csv и sampling.csv. Скрипт читает
каждый файл один раз и строит индекс отборов в памяти; повторных чтений CSV
для каждого поступления нет. Файлы не изменяются.
По умолчанию sampling.csv ищется рядом с файлом, указанным в CSV_PATH.
Другой путь задаётся SAMPLING_CSV_PATH.

Для sampling.csv нужны заголовки:
Название; Номер акта отбора проб; Дата отбора проб; Наименование объекта;
Место отбора проб. Колонка Ссылка необязательна.
Разделитель ;, UTF-8, корректные CSV-кавычки обязательны.

Чисто числовой «Отбор проб» поступления разрешается как точное значение
«Название» в sampling.csv (после удаления внешних пробелов, без преобразования
в число и без потери ведущих нулей). Нет перехода к трактовке этого значения
как номера акта или ID Space, если старый ID не найден.

Пример: 183685 → акт 129, 12.03.2025, РЕК М3 км 86-124 II ПК, ПК230.
Номер 129 после разрешения связи является допустимым числовым номером акта.

Если в строке sampling.csv есть ссылка, дополнительно проверяются хост портала,
list_id=176 и совпадение element_id с «Название». Для разрешения связи документ
самого акта не скачивается. Отсутствие ссылки на акт не мешает связи.
Полностью совпадающие по нормализованным реквизитам повторы старого ID допустимы;
различающиеся или неполные повторы блокируют автоматическое назначение.

## Сопоставление

Основной ключ поступления остаётся: дата поступления + материал + изготовитель
+ номер акта. Для разрешённого старого ID кандидаты дополнительно сверяются
по дате отбора, объекту и месту из sampling.csv. Только один оставшийся кандидат
может пройти дальше; несколько остаются AMBIGUOUS. Это позволяет различить
одноимённые акты разных объектов и мест отбора.
Для нечислового «Отбор проб» действует прежнее правило v2 без дополнительной
сверки через sampling.csv. Реквизиты паспорта проверяются как в v2: пустые
значения в БД не мешают, заполненные не должны противоречить CSV.

Перед загрузкой повторяются проверки актуальной записи. Сервер проверяет также
ожидаемые ID/дату/объект/место связанного отбора, затем применяет условное
обновление с проверкой связей в БД. Поля паспорта автоматически не заполняются.
Сохраняются отдельный receipt-state.jsonl, проверка формата, SHA-256,
таймаут транзакции 30 секунд и запрет перезаписи имеющихся документов.

## Первый запуск

Не задавайте RETRY_REPORT — нужен полный проход с новым сопоставлением.
Если переменные остались экспортированы от восстановления протоколов:

```bash
unset RETRY_REPORT RECOVER_UNCERTAIN REPAIR_MISSING
```

```bash
DRY_RUN=1 CSV_PATH=./legacy-data/receivedMaterials.csv \
SAMPLING_CSV_PATH=./legacy-data/sampling.csv \
npx tsx scripts/import-files/import-receipts.ts
```

Используйте прежние настройки подключения и доверенного CA. При стандартном
расположении SAMPLING_CSV_PATH можно опустить.
DRY_RUN не скачивает документы, не меняет БД или журнал состояния; создаёт отчёт.
Журнал и старые отчёты не удаляйте, даже если часть материалов уже импортирована.

Новые статусы входят в review:
- SAMPLING_SOURCE_NOT_FOUND — старого ID нет в sampling.csv;
- SAMPLING_SOURCE_INCOMPLETE — нет номера, даты, объекта или места;
- SAMPLING_SOURCE_ID_CONFLICT — ссылка акта противоречит «Название» или некорректна;
- SAMPLING_SOURCE_AMBIGUOUS — старый ID встречается с противоречащими данными;
- SAMPLING_DETAILS_CONFLICT — основной ключ поступления совпал, но реквизиты
  связанного отбора не совпали с sampling.csv.

В отчёте legacySamplingReference сохраняет исходную ссылку-значение,
resolvedSampling — найденные реквизиты отбора. Поле samplingActNumber из CSV
сохраняет исходное значение для прозрачности; разрешённый номер находится
в resolvedSampling.number. NOT_FOUND означает отсутствие кандидата по основному
ключу после разрешения связи, AMBIGUOUS — несколько оставшихся кандидатов.

После проверки отчёта — пробные три документа: та же команда с
DRY_RUN=0 MAX_FILES=3. Полный импорт — MAX_FILES=0. Работайте с полными CSV,
чтобы обнаруживались конфликты источников во всей выгрузке.

Типизация клиента и сервера прошла на доступной схеме. Изолированные тесты
проверили разрешение старого ID в числовой номер акта, неизвестный ID,
противоречащие повторы, весь путь dry-run/загрузки с имитацией HTTP/БД,
неоднозначность, противоречащие реквизиты и защиту существующих документов.
На боевой БД обновление не запускалось.
