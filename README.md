# Восстановление импорта протоколов Space

## Установка

Архив содержит четыре файла кода и эту инструкцию. Перенесите файлы в корень
проекта с сохранением каталогов:

- scripts/import-files/import-protocols.ts — заменить;
- server/api/lab/test-protocol/migration/upload.post.ts — заменить;
- server/api/lab/test-protocol/migration/verify/[id].get.ts — добавить;
- shared/utils/migration-document.ts — добавить (нужен и серверу, и скрипту).

Существующий server/services/lab/protocol-migration.service.ts не изменяется.
Новых npm-зависимостей и миграций схемы БД нет. Используются зависимости уже
работающего скрипта. Остановите другие экземпляры импорта протоколов.
Сначала разверните обновлённый сервер: npx nuxt typecheck, затем обычная
сборка и перезапуск вашего процесса Space. Только после этого запускайте клиент.

На компьютере запуска должны остаться исходный полный testProtocols.csv,
protocol-state.jsonl и исходный отчёт. Не очищайте журнал, не удаляйте уже
загруженные документы и не меняйте SPACE_BASE_URL на другой сервер.
Если ранее задан PROTOCOL_STATE, используйте тот же путь.

## Что исправлено

В присланном upload.post.ts не было увеличенного таймаута транзакции.
Теперь maxWait=10000, timeout=30000 миллисекунд; запись файла выполняется
до транзакции. Изменение пути в БД и запись аудита остаются атомарными.
Это устраняет ограничение в 5 секунд, но не гарантирует отсутствие других
причин HTTP 500. При неоднозначном результате commit файл не удаляется,
пока сервер не подтвердит, что запись БД на него не ссылается.

Поддерживаются PDF, JPEG, PNG и обычный XLSX, формат определяется по байтам.
Проверка PNG структурная, а не полное декодирование изображения. Для XLSX
проверяется структура ZIP и основные XML-части; полный контроль CRC и всех
частей Office не выполняется. Архивы с макросами, шифрованием, ZIP64 и
неподдерживаемой структурой отклоняются. Лимит файла — 50 МиБ.
XLSX сохраняется как XLSX: просмотр в браузере зависит от вашего интерфейса.

Повторный проход выбирает только FAILED и UNCERTAIN из RETRY_REPORT.
Совпадение с БД и неоднозначные источники проверяются по полному CSV.
Новый endpoint проверяет наличие прикреплённого файла и SHA-256.
Если ранее неопределённая загрузка уже сохранена и SHA-256 совпадает с
журналом, повторного скачивания/загрузки нет: фиксируется SUCCESS.
Если пути в БД нет, восстановление UNCERTAIN разрешено только при наличии
старой SHA-256 и совпадении с повторно скачанным документом.
Путь указан, а файла нет/он недоступен, либо SHA-256 различается — ручная проверка.
Существующие документы не перезаписываются; посторонние файлы на диске не удаляются.

Три записи ID 11681, 11813, 11829 оставлены для ручной проверки из-за
номеров-заглушек. Другие номера без букв и цифр также не импортируются.
Из 196 ошибок исходного отчёта до 193 могут пройти дальнейшую проверку;
точное количество зависит от текущего состояния сервера.
31 спорная строка, 1789 несовпадений и 1282 неоднозначных совпадения этим
повторным проходом не обрабатываются.

## Резервная копия

В корне проекта, до реального запуска (при нестандартном PROTOCOL_STATE
подставьте фактический путь журнала):

```bash
cp -- scripts/import-files/protocol-state.jsonl "scripts/import-files/protocol-state.jsonl.backup-$(date +%Y%m%d-%H%M%S)"
cp -- scripts/import-files/protocol-report-2026-09-30T13-59-07-436Z-392581.jsonl "scripts/import-files/protocol-report-original.backup-$(date +%Y%m%d-%H%M%S).jsonl"
```

## 1. Проверка без скачивания

```bash
DRY_RUN=1 RECOVER_UNCERTAIN=1 \
RETRY_REPORT=./scripts/import-files/protocol-report-2026-09-30T13-59-07-436Z-392581.jsonl \
CSV_PATH=./legacy-data/testProtocols.csv \
npx tsx scripts/import-files/import-protocols.ts
```

Используйте настройки подключения и CA из успешного запуска миграции.
Команды не отключают проверку TLS. Если нужен собственный CA, задайте
NODE_EXTRA_CA_CERTS с путём к доверенному PEM-файлу.

DRY_RUN читает БД и проверяет файлы на Space, создаёт новый отчёт, но не
скачивает документы старого портала, не меняет журнал состояния или БД.
READY/READY_TO_RETRY — предварительная готовность: байты старого портала
и их SHA-256 будут проверены только при реальном скачивании.
RECONCILED_SUCCESS в dry-run означает подтверждённый файл на Space;
запись SUCCESS в журнал добавляется только в реальном режиме.

## 2. Пробный импорт

```bash
DRY_RUN=0 MAX_FILES=3 RECOVER_UNCERTAIN=1 \
RETRY_REPORT=./scripts/import-files/protocol-report-2026-09-30T13-59-07-436Z-392581.jsonl \
CSV_PATH=./legacy-data/testProtocols.csv \
npx tsx scripts/import-files/import-protocols.ts
```

MAX_FILES ограничивает число попыток скачать и затем загрузить документ,
а не количество проверенных записей или сверок уже сохранённых файлов.
Проверьте новые документы в Space и итоговый отчёт.

## 3. Остальные ошибки

```bash
DRY_RUN=0 MAX_FILES=0 RECOVER_UNCERTAIN=1 \
RETRY_REPORT=./scripts/import-files/protocol-report-2026-09-30T13-59-07-436Z-392581.jsonl \
CSV_PATH=./legacy-data/testProtocols.csv \
npx tsx scripts/import-files/import-protocols.ts
```

Продолжайте указывать исходный отчёт: журнал защищает от повторной загрузки
уже завершённых назначений. Флаг восстановления не отменяет проверки SHA-256.

Счётчики: success — новые загрузки; reconciled — подтверждённые по SHA-256
неопределённые загрузки; existing — уже прикреплённые проверенные документы;
ready — готовность в dry-run; review — ручная проверка; failed — ошибки;
skipped — строки вне выбранного набора ошибок.

## Проверки патча

В изолированном окружении прошла проверка типов клиента и серверных файлов.
Тесты с имитацией БД/HTTP проверили dry-run, сверку SHA-256, отказ при изменении
документа, отсутствие перезаписи, восстановление ошибок, поддержку форматов,
таймаут транзакции и очистку после отката. На вашей боевой БД патч не запускался.
