# Импорт документов о качестве поступлений материалов

## Установка

Перенесите восемь файлов кода из архива в проект с сохранением каталогов.
Новые маршруты: /api/lab/receipt-material/migration/summary,
/api/lab/receipt-material/migration/<id>,
/api/lab/receipt-material/migration/verify/<id>,
/api/lab/receipt-material/migration/upload (POST).

Скрипт scripts/import-files/import-receipts.ts запускается на том же компьютере,
где работал импорт протоколов, с теми же настройками Space/CA/NTLM.
На компьютере запуска нужен также shared/utils/migration-document.ts.
Этот общий детектор совпадает с версией восстановления протоколов v3.
Остальные файлы новые; скрипт и маршруты протоколов не изменяются.
Новый server/utils/migration-stored-file.ts используется эндпоинтами материалов.

Схема БД не меняется. Нужны уже использованные зависимости csv-parse и httpntlm,
запуск через tsx. Сначала npx nuxt typecheck, затем обычная сборка и перезапуск
Space. Модуль проверен по присланной schema(4).prisma; если она менялась,
результат проверки типов в полном проекте обязателен перед сборкой.

Права учётной записи: lab.receipt-materials VIEW для чтения и UPDATE для загрузки.
Если nginx применяет Negotiate к новым маршрутам, настройте для них тот же
проход к приложению, что для работающих маршрутов миграции протоколов.
Не отключайте проверки сессии/прав внутри Space. HTTP 401 с HTML/Negotiate
указывает на nginx; повторный ввод пароля в скрипте его не устраняет.
Не меняйте весь /api ради миграции: используйте существующий проверенный
шаблон конфигурации миграционных маршрутов и проверьте nginx -t.

## CSV и сопоставление

Полный файл: legacy-data/receivedMaterials.csv. Разделитель — точка с запятой,
UTF-8 с BOM или без него. Кавычки внутри полей должны быть оформлены по CSV.
При неправильном количестве колонок скрипт останавливается: он не сдвигает поля
и не пропускает повреждённые строки незаметно.

Нужны заголовки:
Материал; Дата поступления; Дата документа о качестве; Номер документа о качестве;
Предприятие изготовитель; Отбор проб; Ссылка.
Название и Документ о качестве используются для отчёта, если присутствуют.
Название старой записи и element_id ссылки НЕ считаются ID Space.

Ключ сопоставления состоит из шести значений:
1. Дата поступления.
2. Материал.
3. Дата документа о качестве.
4. Номер документа о качестве.
5. Предприятие изготовитель.
6. Номер акта отбора проб (CSV «Отбор проб»).

Сравнение не учитывает регистр, пробелы, ?, №, # и кавычки. Другая пунктуация
сохраняется. Даты DD.MM.YYYY и YYYY-MM-DD приводятся к одному виду.
Импорт выполняется только при единственном совпадении во всей выборке БД.
Равенство нормализованных полей — принятое правило сопоставления, не независимое
доказательство исторической идентичности. Неоднозначности не разрешаются по
первому найденному ID или по порядку строк.

Дата поступления, материал, изготовитель и акт должны быть заполнены.
Номер паспорта разрешено не заполнять, если есть дата документа; дата может
отсутствовать, если есть номер. Пустое значение совпадает только с пустым значением
в БД. Если отсутствуют и номер, и дата — ручная подготовка данных.
Акт с несколькими значениями через ; и номера только из прочерков не импортируются.
Присланный пример: 10 строк, одна без ссылки, одна с документом без номера.
Полная статистика станет известна после запуска на полном CSV и серверной БД.

Пустая ссылка или только прочерки => NO_DOCUMENT_LINK, счётчик noDocument.
Это отсутствие ссылки в выгрузке, а не доказательство отсутствия паспорта вообще.
Не создаются заглушки и пустые файлы. Отсутствие ссылки не считается failed.

Ссылка должна вести на portal.avtodor-eng.ru, list_id=177,
field_id=PROPERTY_1419 с числовыми element_id и file_id.
Ссылки других типов не скачиваются автоматически.
Несколько разных ссылок на одно поступление => MULTIPLE_SOURCE_DOCUMENTS.
Один исходный документ допустим для нескольких разных однозначно сопоставленных
поступлений; каждый получает свой файл. Это не дедупликация хранилища.

## 1. Проверка без скачивания

```bash
DRY_RUN=1 CSV_PATH=./legacy-data/receivedMaterials.csv \
npx tsx scripts/import-files/import-receipts.ts
```

Для проверки только присланного фрагмента подставьте receivedMaterials_part.csv,
но реальный импорт выполняйте с полным файлом: он нужен для выявления конфликтов
между строками. DRY_RUN по умолчанию включён. Проверка запрашивает вход в Space,
читает записи, создаёт JSONL-отчёт, не скачивает документы портала и не меняет БД.
READY — предварительная готовность, ещё без проверки содержимого документа.

## 2. Пробные три документа

```bash
DRY_RUN=0 MAX_FILES=3 CSV_PATH=./legacy-data/receivedMaterials.csv \
npx tsx scripts/import-files/import-receipts.ts
```

Проверьте привязку и открытие файлов в соответствующих записях реестра Space.
MAX_FILES ограничивает число попыток скачивания/загрузки, не число успешных файлов.

## 3. Полный проход

```bash
DRY_RUN=0 MAX_FILES=0 CSV_PATH=./legacy-data/receivedMaterials.csv \
npx tsx scripts/import-files/import-receipts.ts
```

Скрипт использует отдельные receipt-state.jsonl, receipt-import.log и
receipt-report-<время>-<pid>.jsonl в scripts/import-files.
Состояние привязано к серверу Space, ID поступления и исходной ссылке.
Не удаляйте журнал при повторном запуске. Успешные записи не перезаписываются.
Переменные RECEIPT_STATE и RECEIPT_LOG позволяют изменить пути; не подставляйте
журнал протоколов. Перед восстановлением ошибок сделайте копию журнала.

При повторном обычном запуске FAILED можно повторить; UNCERTAIN/UPLOAD_PENDING
без подтверждения остаются для сверки. Клиент не делает автоматический повтор POST.
Поддерживаются режимы восстановления v3: RETRY_REPORT с FAILED/UNCERTAIN,
RECOVER_UNCERTAIN=1; для подтверждённо отсутствующих прикреплённых файлов —
REPAIR_MISSING=1. Применяются только с отчётом и журналом МАТЕРИАЛОВ.
Без старой контрольной суммы неопределённая загрузка не восстанавливается.

## Хранение и форматы

Корень сервера: LAB_FILES_ROOT или /var/www/uploads-storage/files.
Относительный путь:
<объект>/<место отбора>/<дата отбора>/quality_<номер или ID>_<ID поступления>_<UUID>.<расширение>

Объект, место и дата берутся из связанного активного отбора проб в Space.
Запись без активного отбора => NO_ACTIVE_SAMPLING. Номер без значения заменяется
ID только в имени файла; поля записи БД не изменяются.

Поддерживаются PDF/JPEG/PNG/XLSX до 50 МиБ, проверяемые по содержимому.
PNG проверяется структурно, XLSX — как немакросный ZIP с основными XML-частями;
это не полное декодирование изображения или проверка всех данных Office.
HTML-страница авторизации не сохраняется как документ. Неподдерживаемые форматы
отражаются в ошибках для дальнейшей обработки. XLSX может требовать скачивания
вместо встроенного просмотра.

Сервер проверяет исходные поля записи ещё раз, запрещает замену существующего
пути без специального режима восстановления, сохраняет новый файл под уникальным
именем и условно обновляет запись вместе с аудитом в транзакции (30 секунд).
Конфликт изменений оставляет запись без изменения. При неоднозначной ошибке commit
файл не удаляется до подтверждения отсутствия ссылки на него в БД.

## Что прислать после проверки

Итоговые счётчики и созданный receipt-report-*.jsonl. Особенно важны noDocument,
missing, invalidDate, unmatched, ambiguous и review. Неполные/неоднозначные записи
не надо исправлять массовым ослаблением ключа — сначала исследуем причины.

Проверка типов пройдена на доступной схеме. Изолированные тесты с имитацией HTTP/БД
проверили присланный CSV, пустую ссылку/номер, нормализацию, неоднозначность,
несколько источников, dry-run, загрузку, сохранённый путь, конфликт БД и аудит.
На боевом сервере новый модуль пока не запускался.
