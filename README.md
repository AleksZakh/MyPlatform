# Импорт документов протоколов испытаний в Space

Комплект добавляет отдельные маршруты миграции. Существующие CRUD-эндпоинты и миграция актов не заменяются. Схему Prisma менять не требуется.

## Установка

1. Скопируйте `server/` и `scripts/` из архива в корень проекта с сохранением структуры.
2. Выполните `npx nuxt typecheck`, обычную сборку и перезапуск Space.
3. Для загрузки добавьте фрагмент `nginx/protocol-upload.conf` внутрь HTTPS-блока `server` Space. Проверьте upstream: в примере `127.0.0.1:3000`, как в присланной конфигурации. Затем `sudo nginx -t` и, только при успехе, `sudo systemctl reload nginx`. Не заменяйте весь конфиг этим фрагментом. Авторизацию и права проверяет Space; Kerberos-маршрут входа не меняется.
4. Пользователю миграции нужны VIEW и UPDATE для `lab.test-protocols`. Маршруты не нужно добавлять в публичные исключения middleware.
5. Полный CSV положите в `legacy-data/testProtocols.csv`. Присланный `testProtocols_part.csv` содержит только 10 записей. Для реального импорта используйте полный файл, чтобы проверка нескольких ссылок на одну запись охватывала весь набор.

## CSV и сопоставление

Разделитель `;`, UTF-8, стандартное CSV-экранирование. Обязательные поля: `Номер`, `Дата`, `Результат испытаний`, `Ссылка`. Единственный пустой заголовок между `Протокол испытаний` и `Результат испытаний` в присланной структуре из 10 столбцов распознаётся как `Ссылка`. Переименовывать его вручную не обязательно. Другие структуры не угадываются.

Ключ: номер + дата + результат испытаний. При сравнении игнорируются регистр, пробельные символы, ?, №, # и кавычки. Прочие знаки, включая /, -, точки и подчёркивания, сохраняются. Даты DD.MM.YYYY и ISO сравниваются как календарные даты; невозможные даты отклоняются. Пустые составляющие не сопоставляются. Только единственный кандидат разрешён для автоматического импорта. Это согласованное правило сопоставления, не доказательство исторической идентичности: проверьте первые документы визуально.

Поле `Поступление материала` содержит старый ID и не сравнивается с ID Space. Оно сохраняется в отчёте. Несколько разных ссылок для одного ID -> MULTIPLE_SOURCE_DOCUMENTS, ручная проверка. Пока у протокола одно поле пути, автоматически выбирать первую ссылку нельзя.

## Запуск из корня проекта

Зависимости уже использовались для актов: `tsx`, `csv-parse`, `httpntlm`. Запускайте через tsx, не через ts-node.

Проверка полного файла без скачивания и изменения лабораторных данных:

```bash
DRY_RUN=1 CSV_PATH=./legacy-data/testProtocols.csv npx tsx scripts/import-files/import-protocols.ts
```

DRY_RUN=1 включён по умолчанию. Space всё равно запрашивает вход; создание сессии/журналирование входа возможны. Пароль старого портала при проверке не нужен.

Первые три попытки загрузки:

```bash
DRY_RUN=0 MAX_FILES=3 CSV_PATH=./legacy-data/testProtocols.csv npx tsx scripts/import-files/import-protocols.ts
```

После проверки документов в Space, полный проход:

```bash
DRY_RUN=0 MAX_FILES=0 CSV_PATH=./legacy-data/testProtocols.csv npx tsx scripts/import-files/import-protocols.ts
```

MAX_FILES ограничивает попытки скачивания, а не число успешных загрузок; при DRY_RUN полный отчёт формируется без этого ограничения. Пауза между скачиваниями по умолчанию 3 секунды. Новые файлы допускаются PDF/JPEG, максимум 50 MiB. Проверяется сигнатура, HTML страницы входа не сохраняются как документы. Сигнатура не заменяет проверку полной целостности PDF/JPEG.

## Авторизация и TLS

Логин/пароль Space и старого портала запрашиваются отдельно; пароль скрыт и не сохраняется в журналах. NTLM и cookie обрабатываются как в работающем импорте актов. Возможны SPACE_LOGIN, SPACE_PASSWORD, PORTAL_LOGIN, PORTAL_PASSWORD, PORTAL_DOMAIN (по умолчанию CORP), SPACE_BASE_URL. `.env` автоматически не читается. Секреты не записывайте в код и не присылайте в чат.

При недоверенном сертификате настройте доверенную цепочку CA, например:

```bash
NODE_EXTRA_CA_CERTS=/absolute/path/company-ca.pem DRY_RUN=1 npx tsx scripts/import-files/import-protocols.ts
```

Скрипт не отключает проверку TLS. `fetch failed` до чтения данных обычно требует проверки сети/сертификата. HTTP 401 с HTML и WWW-Authenticate: Negotiate указывает на nginx, а не на отказ JSON API Space.

## Хранилище и защита повторного импорта

Корень: серверный LAB_FILES_ROOT либо `/var/www/uploads-storage/files`.

Путь: `Объект/Место/Дата_отбора/protocol_Номер_ID_UUID.pdf` (или .jpg).

Дата папки — дата связанного отбора проб, чтобы документы одной записи лежали вместе. Она не заменяет дату протокола. Метаданные папки берутся из БД. Протокол без действующего SamplingTest попадает в NO_ACTIVE_SAMPLING.

Сервер требует ID протокола и ожидаемые номер/дату/результат, проверяет их перед записью. Существующий файл не заменяется. Условное обновление защищает от изменений между чтением и записью, привязка и аудит выполняются в транзакции. При ошибке транзакции новый файл удаляется. При аварийном завершении процесса между записью файла и транзакцией возможен непривязанный файл: автоматической уборки нет.

После начала POST потеря ответа отмечается UNCERTAIN. Автоматический повтор такого POST запрещён: следующий проход проверяет путь в БД. Если пути нет, HISTORY_WITHOUT_DB_PATH требует ручной проверки. Наличие пути не доказывает физическую доступность файла.

## Журналы

Рядом со скриптом:
- `protocol-state.jsonl` — состояние продолжения, дописывается;
- `protocol-import.log` — журнал попыток, дописывается;
- `protocol-report-ДАТА-PID.jsonl` — отдельный отчёт каждого запуска: исходная строка (номер логической CSV-записи), ссылка, номер/дата/результат, старое поступление, ID кандидатов, результат.

Не удаляйте журналы между проходами. Они отдельны от журналов актов. Переопределения: PROTOCOL_STATE и PROTOCOL_LOG. Чужое пространство ключей в state останавливает запуск. Только один процесс на один state; оставшийся после аварии .lock удаляйте лишь после проверки, что процесс завершён.

Статусы: READY (проверка), SUCCESS, EXISTING, NOT_FOUND, AMBIGUOUS, MISSING_FIELDS, EMPTY_NORMALIZED_KEY, INVALID_DATE, INVALID_URL, MULTIPLE_SOURCE_DOCUMENTS, NO_ACTIVE_SAMPLING, RECORD_CHANGED, HISTORY_WITHOUT_DB_PATH, FAILED, UNCERTAIN. Счётчики относятся к строкам текущего прохода, не обязательно уникальным протоколам.

Пагинация серверного списка по ID; при активных массовых удалениях/переносах записей во время чтения offset-страницы могут смещаться. Избегайте параллельной массовой правки протоколов в период миграции. Скрипт обнаруживает повторные ID и перед записью повторно проверяет совпадение.

## Проверено перед передачей

Проверка типов новых маршрутов/сервиса в доступном окружении и скрипта; тесты с подставными API/БД: CSV-заголовок, даты, ключи, режим без скачивания, категории пропусков, лимит, продолжение без повторного POST, JPEG, серверные права, запрет замены, изменение записи, отсутствие SamplingTest, уборка при конфликте. Реального доступа к вашему порталу и боевой БД из этого окружения нет. Полный `npx nuxt typecheck` выполните в проекте.
