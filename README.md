# Поддержка WebP — патч v4 поверх импорта материалов v3

Замените shared/utils/migration-document.ts в проекте на сервере Space И на
компьютере запуска скрипта. Сервер: npx nuxt typecheck, обычная сборка и перезапуск.
Клиент import-receipts.ts v3 и серверные эндпоинты менять не нужно: они используют
этот общий определитель, его расширение и MIME. Новых зависимостей и миграций БД нет.
Обновление общего файла также добавляет WebP в миграционные эндпоинты протоколов,
использующие тот же определитель. Тексты некоторых старых ошибок могут пока
перечислять прежний набор форматов; на распознавание это не влияет.

WebP сохраняется без перекодирования с расширением .webp и MIME image/webp.
Проверяются RIFF/WEBP, объявленная длина, границы блоков, базовые заголовки VP8/VP8L,
расширенный VP8X и размеры изображения. Это структурная проверка, не полное
декодирование. Поддержаны статичные lossy/lossless/alpha изображения.
Анимация и некорректные структуры отклоняются. Лимит остаётся 50 МиБ.
Спецификация: https://developers.google.com/speed/webp/docs/riff_container

## Подготовка

Сохраните receipt-state.jsonl и исходный отчёт. Не удаляйте журнал или документы.
Используйте тот же SPACE_BASE_URL, CSV и настройки доверенного CA.
В RETRY_REPORT указывайте исходный отчёт полного импорта материалов:
receipt-report-2026-10-01T13-11-51-252Z-961529.jsonl.
Из него выбираются FAILED/UNCERTAIN; здесь ожидается 101 назначение.
Полный CSV и sampling.csv по-прежнему нужны для проверки сопоставления.

## Проверочный запуск

```bash
DRY_RUN=1 RECOVER_UNCERTAIN=0 REPAIR_MISSING=0 \
RETRY_REPORT=./scripts/import-files/receipt-report-2026-10-01T13-11-51-252Z-961529.jsonl \
CSV_PATH=./legacy-data/receivedMaterials.csv \
SAMPLING_CSV_PATH=./legacy-data/sampling.csv \
npx tsx scripts/import-files/import-receipts.ts
```

Здесь нет UNCERTAIN, поэтому режимы восстановления не нужны.
DRY_RUN проверяет кандидатов и состояние файлов Space; не скачивает старые
документы, не изменяет журнал состояния или БД. Создаёт новый отчёт.

## Пробные три попытки

Повторите команду, заменив DRY_RUN=1 на DRY_RUN=0 MAX_FILES=3.
Проверьте привязку и открытие документов, включая WebP. Первый кандидат может
быть PDF для ID 1079: у него был HTTP 500 при чтении карточки.
Если 500 повторится, нужен серверный лог этой ошибки; патч её причину не исправляет.

## Остальные ошибки

```bash
DRY_RUN=0 MAX_FILES=0 RECOVER_UNCERTAIN=0 REPAIR_MISSING=0 \
RETRY_REPORT=./scripts/import-files/receipt-report-2026-10-01T13-11-51-252Z-961529.jsonl \
CSV_PATH=./legacy-data/receivedMaterials.csv \
SAMPLING_CSV_PATH=./legacy-data/sampling.csv \
npx tsx scripts/import-files/import-receipts.ts
```

Указывайте прежний исходный отчёт и сохраняйте журнал: завершённые назначения
будут пропущены. Скрипт не перезаписывает уже прикреплённые документы.
Если возникнут новые UNCERTAIN, отдельно проверяем результат сохранения.

Проверены типы клиента и сервера, реальные WebP-файлы с потерями, без потерь
и с прозрачностью, отказы на обрезанные RIFF/HTML, регрессионные сценарии
импорта и приём WebP эндпоинтом с имитацией HTTP/БД.
На боевом сервере патч пока не запускался; просмотр WebP в конкретном интерфейсе
Space нужно проверить после пробной загрузки.
