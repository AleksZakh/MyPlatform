# Редактирование Реестра: 30 минут

## Установка

1. Сохраните резервные копии заменяемых файлов.
2. Скопируйте app/, server/, scripts/ в корень проекта с сохранением путей.
3. Обновите название и описание существующего права в БД:

```bash
npx tsx scripts/update-lab-edit-window-labels.ts
```

Скрипт меняет только name и description ресурса lab.incoming-control.edit-lock-override. Назначения, активность и связи ресурса не меняются. Если ресурса нет, скрипт сообщит 0 обновлённых записей. ensure-lab-edit-lock-resource.ts включён с исправленными подписями для будущего создания ресурса; для обновления текста запускать его не нужно.

4. Пересоберите и перезапустите приложение, обновите страницу и заново откройте карточку.

Миграция схемы БД не нужна.

## Поведение

Отбор проб и поступление материала редактируются в течение 30 минут от создания записи. Протокол — в течение отдельных 30 минут от своего первого сохранения. Последующие сохранения отсчёт не перезапускают. Первое создание протокола по-прежнему разрешено независимо от возраста основной записи. Специальное право обхода блокировки работает как раньше; способы его проверки не менялись.

Изменение применяется также к существующим записям: запись возрастом 15 минут снова проходит временную проверку, запись старше 30 минут — нет. Это не новые 30 минут с момента установки обновления.

В серверном сервисе изменена общая константа INCOMING_CONTROL_EDIT_WINDOW_MINUTES. Сроки expiresAt, remainingSeconds и сообщения ошибок рассчитываются из неё. Подписи формы используют windowMinutes из ответа сервера, резервное значение — 30.

В createModal.vue сохранены последние изменения: обычный input места отбора без списка, возможность заполнения протокола при создании и контроль последовательности дат.

## Проверки

Проверены функции действительного серверного сервиса с имитацией запросов прав: после 10 минут блокировки нет; 29:59 разрешено; 30:00 запрещено; отдельный отсчёт протокола; первое создание протокола; обход блокировки; сформированные сервером сроки. Компонент Vue скомпилирован, упоминания старого интервала в поставляемых подписях удалены.

Сервис взят из ранее подготовленного incoming-control-edit-lock.service.ts. Доступный архив incoming-control-location-resolver-v1.zip подтверждает его вызовы из PUT endpoint. Если вы после этого меняли сам сервис локально, перенесите изменение константы (10 → 30) в свою актуальную версию вместо полной замены. Реальная БД, сервер пользователя и полная production-сборка здесь не запускались.
