# Упрощённое сопоставление лабораторных документов

Скопируйте scripts/analyze-lab-simple.ts в scripts вашего проекта MyPlatform. Используются установленные зависимости @prisma/client, csv-parse, tsx. Скрипт самостоятельный, предыдущие файлы не заменяет.

Из корня проекта, используя имеющийся снимок:

```bash
npx tsx scripts/analyze-lab-simple.ts ./legacy-data ./lab-simple-01 --snapshot ./lab-audit-02/snapshot.json
```

Или напрямую с текущей БД (DATABASE_URL как для прежних скриптов):

```bash
npx tsx scripts/analyze-lab-simple.ts ./legacy-data ./lab-simple-02
```

Папка результата должна быть новой; её родитель должен существовать. В папке входа ожидаются sampling.csv, receivedMaterials.csv, testProtocols.csv: CSV UTF-8, разделитель `;`. Заголовки читаются по названиям, а не по позиции. Поддержаны кавычки, BOM и многострочные CSV-ячейки. Отсутствие обязательного столбца завершает запуск ошибкой. Пустая таблица с заголовками допустима.

## Наборы сравнения

| Сущность | Все сравниваемые поля |
|---|---|
| Отбор проб | Дата отбора проб, Наименование объекта, Место отбора проб, Номер акта отбора проб |
| Поступление материалов | Дата поступления, Материал, Дата документа о качестве, Номер документа о качестве, Предприятие изготовитель |
| Протокол испытаний | Дата, Номер, Результат испытаний |

Для отборов применён набор пользователя. Для поступлений и протоколов наборы выбраны в этом скрипте и явно показаны здесь; при необходимости редактируются в specs в начале файла. Примечания, ПЛП и прочие поля не участвуют. Связи между тремя таблицами не проверяются: каждая сопоставляется самостоятельно.

Изначально обязательно наличие всех четырёх значений у отбора; у поступления — даты поступления и материала; у протокола — даты и номера. Остальные поля выбранного набора тоже сравниваются: пусто равно пусто, но не заполненному значению. Скрипт не считает два пустых обязательных значения достаточным основанием для совпадения.

Одинаковая нормализация применяется к CSV и Space:
- игнорируются символы ? № #;
- игнорируются прямые и типографские кавычки, апострофы, обратная кавычка;
- игнорируется регистр;
- удаляются все пробельные символы, в том числе внутри текста: ПК 1+00 = ПК1+00;
- даты DD.MM.YYYY и ISO приводятся к YYYY-MM-DD с проверкой календарной корректности;
- цифры, ведущие нули, дефисы, точки, запятые, плюсы и косые черты сохраняются. Например, 01/02 не равно 0102, а 001 не равно 1. Е и ё не отождествляются.

Нормализация применяется только в памяти; исходные CSV и БД не изменяются. Возможные коллизии после удаления символов выявляются по числу кандидатов. Одно уникальное совпадение считается установленной принадлежностью по выбранному правилу, а не независимой проверкой исторического происхождения файла.

## Статусы

- MATCH — ровно одна активная запись Space совпала по всем полям набора после нормализации.
- AMBIGUOUS — совпали несколько записей, их ID перечислены в candidates. Ни одна не выбрана.
- NOT_FOUND — ключ заполнен, совпадений нет.
- MISSING_FIELDS — пустые обязательные значения, точные названия перечислены в missing_fields.
- INVALID_DATE — некорректная дата, причина в detail.

Удалённые записи Space исключаются. Мягко удалённые связанные справочники отдельно не фильтруются: используются значения, связанные с активной основной записью. Индекс набора полей строится один раз для каждой таблицы; отдельный запрос к БД на каждую строку не выполняется.

## Результаты

- sampling.csv, receipts.csv, protocols.csv — результаты со всеми исходными и нормализованными ключевыми значениями;
- matched.csv и matches.json — только уникальные совпадения, ссылки, имя файла, старые ID и ID Space;
- repeated-targets.csv — несколько исходных строк сопоставились с одной записью Space. Это может быть несколько документов одной записи или коллизия исходных данных; скрипт не удаляет их автоматически;
- *-db-issues.csv — записи БД с неполным ключом или некорректной датой;
- summary.json — итоговые числа, использованные поля и дата снимка.

Столбец row — порядковый номер CSV-записи с заголовком, не физическая строка при многострочных ячейках. Отчётные CSV экранируют начальные символы формул при открытии в Excel; в JSON значения сохраняются без этого экранирования.

Ссылка читается из «Ссылка» или столбца с пустым заголовком у протоколов. Из URL извлекаются element_id и file_id. link_status проверяется независимо: MATCH без VALID означает совпадение записи, но ссылка требует проверки. URL не открываются. В matched.csv такие строки остаются с явным статусом. Существующий загрузчик версии 2 не принимает matches.json вместо download-plan.json: сначала оцените отчёт новой сверки.

Чтение БД выполняется в READ ONLY / REPEATABLE READ транзакции, таймаут 180 секунд. Схема соответствует рабочему экспортёру версии 2. При --snapshot используются данные на дату снимка, не текущее состояние БД. Скрипт не скачивает документы, не меняет пути, не создаёт назначений в БД.

Самопроверка без БД и CSV:

```bash
npx tsx scripts/analyze-lab-simple.ts --self-test
```

Проверены нормализация, даты, неоднозначность, пустые ключи, исключение удалённых записей и 50 000 синтетических совпадений. Запуск на вашей БД ещё не выполнен.
