# Space — поддержка объектов AD contact

Устанавливать поверх этапа 3 (включая точечное обновление аббревиатур). В архив входят только изменённый загрузчик, преобразователь контактов и тесты.

## Изменения

- ГК, УК и «Платные дороги» читают AD-объекты `user` и `contact` внутри указанного DN.
- Для контактов не требуется `sAMAccountName`; идентификатором выступает `objectGUID`.
- При чтении обрабатываются LDAP-результаты `users` и `other`.
- Ранее кэшированный пустой ответ не используется после обновления (ключ кэша изменён).
- DN берётся из серверной переменной `AD_PHONEBOOK_*` во время работы приложения; `NUXT_AD_PHONEBOOK_*` остаётся поддерживаемым резервным вариантом.
- Авторизация, импорт пользователей «Инжиниринга» и работа групп AD не меняются.

Контакты без учётной записи Space не могут самостоятельно редактировать карточку; администратор с правом `admin.users / UPDATE` может менять локальные дополнительные поля. Поля AD остаются только для чтения.

## Установка

После резервной копии проекта распакуйте архив в корень проекта, затем соберите новый релиз обычным способом и активируйте его. Если обновление устанавливается напрямую в работающий проект:

```bash
npm run build
```

Перезапустите приложение способом, предусмотренным вашей схемой релизов. На текущем сервере процесс запущен как `space-app` от пользователя `space`.

## Проверка

```bash
node --import tsx --test tests/phone-directory-contact.test.ts tests/phone-directory-acronym.test.ts
```

Откройте каждую из трёх вкладок и проверьте JSON `/api/contacts?scope=...`: вместо пустого массива должны появиться контакты при наличии доступных объектов и необходимых атрибутов в AD. Сообщение `[PHONEBOOK] scope=... accounts=... contacts=... skipped=... total=...` в серверном журнале показывает число обработанных записей без персональных данных.

Если массив по-прежнему пустой, проверьте правильность DN и то, что контактам доступен атрибут `objectGUID` и имя (`displayName` или `cn`).
