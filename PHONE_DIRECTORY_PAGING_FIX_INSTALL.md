# Space — исправление LDAP-пагинации телефонного справочника

Это точечное обновление поверх ранее установленного исправления объектов `contact`.

## Причина

`activedirectory2` при обычном поиске отправляет контроль первой страницы, но в используемой версии `ldapjs` переход к следующим страницам выполняется только при заданном параметре `paged`. Из-за этого ГК и «Платные дороги» возвращали ровно 1000 записей.

## Изменения

- В LDAP-запросе включено автоматическое чтение страниц: `paged: { pageSize: 500 }`.
- `sizeLimit: 0` оставляет общий лимит записей неограниченным.
- Ключ кэша обновлён до `contacts-v3`, чтобы не возвращать прежние 1000 контактов в течение часа.
- Фильтр контактов, права, авторизация, синхронизация пользователей и БД не менялись.

## Установка

Распакуйте архив в корень исходников Space с сохранением структуры и соберите/разверните очередной релиз вашим штатным механизмом. Новых переменных и миграций нет.

Если проект запускается напрямую из исходников:

```bash
npm run build
```

Перезапуск `space-app` выполните штатным механизмом публикации.

## Проверка после установки

На сервере:

```bash
sudo grep '\[PHONEBOOK\]' /home/space/.pm2/logs/space-app-out-*.log | tail -n 15
```

В браузере (DevTools Console):

```javascript
fetch('/api/contacts?scope=group').then(r => r.json()).then(d => console.log(d.contacts.length))
```

Если в AD действительно более 1000 подходящих контактов, новое значение должно превысить 1000.

Местные тесты:

```bash
node --import tsx --test tests/phone-directory-contact.test.ts
```

LDAP-сервер корпоративной сети в среде разработки недоступен, поэтому реальную полноту данных нужно подтвердить после установки.
