# Групповые чаты Space

Обновление поверх Space-chat-invitation-id-fix.zip (исправления приглашений и поиска AD уже должны быть установлены).

## Возможности

- Кнопка «Создать группу» в окне сообщений: название до 120 символов и выбор активированных пользователей. До 100 участников, включая создателя. До 20 новых групп от одного пользователя в сутки.
- Группы отображаются вместе с личными диалогами, имеют подписи авторов, счётчик непрочитанных и обновления через WebSocket.
- Все текущие участники видят ВСЮ историю, включая сообщения до вступления. Старые сообщения не увеличивают счётчик непрочитанного у нового участника; это не означает автоматическую отметку «Прочитано» для них.
- В группе кнопка «Участники» открывает состав и настройки.
- Владелец: название, состав, назначение/снятие администраторов, передача владения, архивирование/восстановление.
- Администратор: название, добавление участников, исключение обычных участников. Не может исключить владельца/другого администратора или менять роли.
- Участник: переписка, просмотр состава, выход из группы.
- Для выхода владельцу необходимо передать владение активному участнику. Если группа больше не нужна, её можно поместить в архив. Единственный оставшийся владелец также может архивировать группу.
- Архив доступен для чтения; отправка сообщений запрещена. Владелец может восстановить группу.
- Выход/исключение закрывает доступ к истории и новым сообщениям. Уже прочитанные/сохранённые пользователем сведения отозвать невозможно. Его сообщения в группе сохраняются. При повторном добавлении снова доступна вся история.
- Изменения состава и ролей пишутся в audit_logs.
- Неактивированного доменного сотрудника сначала приглашают в Space существующим механизмом, после его активации добавляют в группу. Добавление из группы не отправляет почтовых приглашений автоматически.
- Удаление сообщений/групп, файлы, упоминания и поиск по переписке не входят в эту поставку.

## Развёртывание

Архив содержит только изменения. Распакуйте в исходный проект, сохраните структуру, добавьте ВСЕ новые файлы и миграцию в Git. Не включайте node_modules, .output и секреты. Отправьте коммит в GitHub.

На сервере:

```bash
cd /var/www/html/MyPlatform
git pull --ff-only
git status --short
space-release prepare
```

После READY используйте фактический ID. Сделайте резервную копию рабочей БД до миграции.

```bash
space-release db-status RELEASE_ID
```

Ожидается `20261012150000_chat_groups`. Если есть другие ожидающие миграции — сначала проверьте их.

```bash
space-release migrate RELEASE_ID
space-release activate RELEASE_ID --db-compatible
space-release status
curl --fail http://127.0.0.1:3000/api/public/health
curl --fail http://127.0.0.1:5050/health
```

Переключение вызывает короткий перерыв. Nuxt и WebSocket должны работать на одном новом релизе: старый WS принимал уведомления только для двух адресатов. После переключения обновите вкладки браузера.

Миграция добавляет поля в chat_conversations/chat_members. Существующие личные диалоги получают тип DIRECT; сообщения и их связи сохраняются. `prisma generate` выполняется внутри prepare.

Откат: схема добавочная и не мешает запуску предыдущего кода. Но предыдущий интерфейс НЕ понимает группы и архивирование. До создания первых групп обычный откат кода допустим. Если группы уже созданы, не возвращайте предыдущую версию в штатную эксплуатацию без отдельного плана: она может отображать группы как личные диалоги и не соблюдает правило архива. Не откатывайте/не удаляйте таблицы вручную. Автоматическая попытка восстановления при неудачном запуске остаётся частью space-release.

## Проверка после установки

1. Создать группу из трёх активированных пользователей; проверить сообщения и имена авторов в разных учётных записях.
2. Добавить четвёртого: ему доступна ранняя история через «Предыдущие сообщения», но нет накопленного счётчика непрочитанного за время до вступления.
3. Назначить администратора; проверить добавление и исключение обычного участника, запрет изменения владельца/администраторов.
4. Исключённому участнику группа перестаёт быть доступна; без WS это обнаруживается при следующем обновлении списка (резервный опрос 15 секунд).
5. Передать владение и выйти прежним владельцем. Проверить архивирование и восстановление.
6. Проверить обычный личный диалог и приглашения доменных сотрудников.

## Проверки при подготовке

- Prisma generate и проверка типов Vue/TypeScript.
- Изолированная PostgreSQL-совместимая PGlite: миграция поверх предыдущей схемы, создание/повтор создания, роли и ограничения, полная история, baseline непрочитанного, выход/исключение/повторное добавление, архивирование, заблокированные учётные записи и личные диалоги.
- Клиентские тесты: выбор активных участников, явное подтверждение изменения, повтор создания с тем же clientId; прежний сценарий повторной отправки сообщений.
- Сборка WS и тесты авторизации, origin, вкладок, уведомлений с несколькими адресатами и ограничения их доставки.
- Корпоративная БД, SMTP/AD, несколько реальных браузерных сессий здесь недоступны. Полную production-сборку выполнит prepare; визуальную и двустороннюю проверку выполните после развёртывания.

Диагностика задержки отправки 3–5 секунд остаётся отдельной задачей. Этот выпуск не заявляет её устранение.

❗❗❗ Инфраструктурный приоритет: перенос рабочей БД с временного сервера на корпоративный PostgreSQL с резервным копированием и проверкой восстановления.
